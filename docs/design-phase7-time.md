## 1. 位置づけ — シミュレーションは正しいのに、画面がそう言っていない

この2つは、調べてみるとどちらも同じ形をしていた ——
**必要なものは既にシミュレーションの側にあり、足りないのは画面の側だけ**である。

| 見えている問題 | 実際の状態 |
| --- | --- |
| 移動がマス単位でカクつく | 描画は**既に補間している**（`renderer.ts`）。ただし補間の速さがシミュレーションの歩調と一致していない |
| 昼か夜か分からない | 時刻は**既に存在する**（`TICKS_PER_HOUR`、TopBar に `HH:MM`）。ただし地図には一切現れない |

つまりどちらも「無いものを作る」のではなく、「**あるものを画面に繋ぐ**」作業になる。
フェーズ6が「場所 —— 何をどこに置くか」なら、こちらは「**時間と動き —— 変化をどう見せるか**」で、
両者は独立して進められる。

このフェーズも、フェーズ6と同じく**ゲーム内容をほとんど増やさない**。
唯一の例外は 3.3（夜と睡眠）で、そこだけは意図的にシミュレーションへ踏み込む。

## 2. なめらかな移動

### 2.1 現状: 補間はあるが、歩調と合っていない

`src/render/renderer.ts` は論理位置へ向かって表示位置を毎フレーム寄せている。

```ts
// 入植者
const speed = 0.009 * deltaMs;
view.displayX += Math.abs(dx) < speed ? dx : Math.sign(dx) * speed;
```

問題は `0.009` が**固定値**で、シミュレーションが1マス進むのにかかる実時間を見ていないこと。
`TICKS_PER_STEP = 2`・`TICK_MS = 200` なので、実際の歩調は次のようになる。

| 速度 | 1マスにかかる実時間 | 補間が1マス渡る時間 | 見え方 |
| --- | --- | --- | --- |
| 1倍 | 400 ms | 約 111 ms | **111 ms で渡り、289 ms 止まる**。これがカクつきの正体 |
| 3倍 | 133 ms | 約 111 ms | ほぼ一致し、ここだけ滑らかに見える |
| 10倍 | 40 ms | 約 111 ms | **渡り終える前に次の歩が来る**ので、表示が論理位置に追いつけず引きずられる |

「マスに沿って動いている」と見えるのは補間が無いからではなく、
**渡ったあと次の歩まで立ち止まっているから**である。
そして 10 倍速では逆に、補間が遅すぎて位置が遅れる。

動物も同じ形で、固定値が `0.007` になっているだけ（`ticksPerStep` は種ごとに 2〜4 と違うのに、
表示側は全種同じ速さで補間している）。

### 2.2 直し方: 固定値をやめ、次の歩までの残り時間で割る

補間の速さを定数で持たず、**「いまの歩が始まってから次の歩までの実時間」**から毎フレーム導く。

```
1マスあたりの実時間 = ticksPerStep × TICK_MS ÷ speed
補間速度 = 1 マス ÷ その時間
```

これで1倍速では 400 ms かけて等速で1マスを渡り、10 倍速では 40 ms で渡る。
**止まっている時間がゼロになる**ので、速度をどこに置いても歩き続けているように見える。
動物は種ごとの `ticksPerStep` を同じ式に入れるだけで、鶏が鹿より遅いことが表示にも出る。

`speed === 0`（停止）のときは補間も止める。止めないと、一時停止したのにスプライトだけが滑る。

### 2.3 状況に応じて速度を変える

いまは `TICKS_PER_STEP = 2` が**全員・全状況で一律**である。変える候補は4つあり、
どれも**既存の数値への乗数**として実装する（特性と同じ形。新しい仕組みを増やさない）。

| 条件 | 倍率（出発点、未実測） | 理由 |
| --- | --- | --- |
| 荷を持っている（`carrying`） | 1.15 倍遅い | 運搬の距離が意味を持つ。倉庫の位置を考える理由になる |
| 森を通る | 1.25 倍遅い | 地形に性格が出る。道を作る動機の下地にもなる |
| 体力が低い | 最大 1.4 倍遅い | 負傷が「数字が減る」以上のものになる |
| 逃走中（`fleeing`） | 1.2 倍速い | 逃げているように見える。狼との距離の緊張が保たれる |

**ただしこれは `GameState` にフィールドを1つ増やす。** `TICKS_PER_STEP` は整数 tick の周期なので、
倍率を掛けると小数になり、「あと何 tick で次の歩か」を持つ場所が要る
（`Colonist.stepProgress: number`）。**このフェーズで唯一、セーブに載る追加**である。

倍率は**掛け算で合成する**（荷を持って森を抜ける負傷者は 1.15 × 1.25 × 1.4）。
上限を置かないと止まって見えるので、合計の遅さには上限（2.0 倍）を設ける。

**移動速度を変えると1年計測が動く。** 運搬が遅くなれば生産チェーン全体が遅くなるので、
`longrun` を取り直して `design-notes.md` に**追記**する（過去の値は消さない）。

## 3. 昼夜の表現

### 3.1 現状: 時刻はあるが、地図にはない

`TICKS_PER_HOUR` は `TICKS_PER_DAY / 24` として定義済みで、TopBar と EventLog は
`HH:MM` を計算して表示している。**1日は既に24時間として流れている。**
足りないのは、それが**地図の上で一度も表現されていない**ことだけ ——
真昼も真夜中も、タイルの色は同じである。

### 3.2 いちばん安い実装: 画面全体に時刻由来の色を重ねる

地形スプライトを描き分けるのではなく、**ワールド全体に1枚のオーバーレイ**を重ねる
（PixiJS の全面矩形、または `ColorMatrixFilter`）。タイル数に依らず一定コストなので、
フェーズ6でマップが4倍になっても影響しない。

| 時刻 | 色 | 不透明度（出発点） |
| --- | --- | --- |
| 05:00–07:00（夜明け） | 暖色 | 0.25 → 0 |
| 07:00–17:00（昼） | なし | 0 |
| 17:00–19:00（日暮れ） | 橙 | 0 → 0.30 |
| 19:00–05:00（夜） | 濃紺 | 0.45 |

**夜でも遊べる暗さに留める。** 0.45 は「夜だと分かる」ためのもので、
「何も見えない」ためのものではない。真っ暗にすると、プレイヤーは夜のあいだ**操作をやめる**か、
10倍速で飛ばすだけになる。

季節で日の長さを変えるのは**やらない**（冬が短日、は自然だが、`CROP_GROWTH_BY_SEASON` と違って
表を1つ足すだけでは済まず、日の出・日の入りの計算が全部の判定に入ってくる）。

### 3.3 魔力灯が初めて視覚的な意味を持つ

夜が暗いなら、**供給の通った魔力灯の周りだけ明るい**のが自然な帰結になる。
`LAMP_RADIUS = 6` と、グリッドが落ちているかどうかは既に計算済みなので、
オーバーレイに穴を開ける（灯の位置に減算する円を置く）だけで済む。

これは表現以上の意味を持つ。魔力灯はいま**気分 +5 だけ**の設備で、
[design-next.md](design-next.md) が「フェーズ2の存在がプレイヤーに伝わっていない」と書いた当のものである。
**暗い夜に灯だけが明るい**なら、灯りは説明を要さない。フェーズ2の見返りが初めて目に見える。

### 3.4 見せると、睡眠が時刻を見ていないことが露見する

これが本フェーズで唯一の、シミュレーション側の判断である。

現在の睡眠は `wantsSleep = colonist.needs.sleep >= SLEEP_THRESHOLD` で、**時刻をまったく見ていない**。
ゲージが溜まれば真昼でも寝に行き、夜でもゲージが低ければ働き続ける。
時刻が数字でしか出ていない現在は誰も気づかないが、**画面が昼だとはっきり言うようになった瞬間、
真昼にベッドへ向かう入植者は「壊れている」ように見える**。

選べる道は2つ。

| 案 | 内容 | 代償 |
| --- | --- | --- |
| (a) 見た目だけ | 睡眠規則は変えない | 昼に寝る絵が残る。**表現が嘘をつく** |
| (b) 夜に寝やすくする | しきい値を時刻で動かす（夜は低く、昼は高く） | 労働時間が変わるので**1年計測を取り直す**必要がある |

**推奨は (b)。** ただし新しい仕組みは作らず、既存の `SLEEP_THRESHOLD` に時刻由来の乗数を掛けるだけにする
（夜 0.7 倍・昼 1.3 倍、出発点）。これは特性・スキル・気分がすべて取っている形と同じで、
乗数が 1 なら導入前とまったく同じ挙動になる。

**寝落ちを強制はしない。** 夜でもゲージが低ければ働けるし、昼でも限界なら寝る ——
夜勤を選べる余地は残す。「夜は寝るもの」を規則にすると、緊急時に手が止まる植民地になる。

## 4. 段階と「動いたと言える条件」

移動（M）と昼夜（N）は独立で、並行して進められる。

| 段階 | 内容 | 動いたと言える条件 |
| --- | --- | --- |
| **M-1** | 補間の速さを歩調から導く | 1倍・3倍・10倍のどれでも、移動中に**止まって見える時間が無い**。停止中はスプライトも動かない |
| **M-2** | 動物の補間を種ごとの `ticksPerStep` から導く | 鶏（4）が鹿（3）より遅く見える |
| **M-3** | 状況で歩速を変える | 荷・地形・体力・逃走がそれぞれ実際に速度を変える。倍率ゼロなら導入前と一致する |
| **N-1** | 時刻由来のオーバーレイ | 夜が夜に見える。タイル数に依らず一定コスト（フェーズ6の 120×120 でも変わらない） |
| **N-2** | 魔力灯が夜に明るい | 供給の通った灯の周りだけ明るい。**グリッドが落ちると暗くなる** |
| **N-3** | 夜に寝やすくする | 睡眠の大半が夜に寄る。ただし昼に限界が来れば昼でも寝る。乗数1で導入前と一致 |

### テスト方針

描画そのものはヘッドレスで検証できないので、**描画に渡す値を純粋関数に切り出して**そこを検証する
（`damage.ts` の損傷段階が既にこの形になっている）。

- **M-1**: 補間速度を返す関数が、速度と `ticksPerStep` から「1マス＝1歩ぶんの実時間」を返すこと。
  `speed === 0` で 0 を返すこと
- **M-3**: 荷を持った入植者が同じ距離により多くの tick を要すること。合成した倍率が上限を超えないこと
- **M-3**: `longrun` を取り直し、1年後の食料・人口が破綻しないこと（数値は notes へ追記）
- **N-1**: 時刻→色の関数が単調で、境界（05:00 / 07:00 / 17:00 / 19:00）で跳ばないこと
- **N-2**: 燃料の切れた炉のグリッドでは灯りの明かりが消えること
- **N-3**: 睡眠開始時刻の分布が夜に寄ること（1年ぶんを数える）。乗数1では導入前と一致すること

## 5. リスクと非目標

| リスク | 対策 |
| --- | --- |
| 夜が暗すぎて遊べない | 不透明度は「分かる」ためのもので「見えない」ためではない（3.2）。実ビルドで見て決める |
| 歩速の変更でバランスが崩れる | M-3 で `longrun` を取り直す。倍率ゼロで導入前と一致することをテストで固定 |
| `stepProgress` がセーブに増える | このフェーズで唯一の保存フィールド。移行は 0 を補うだけ |
| 10倍速で補間が重くなる | 補間は1エンティティあたり数演算で、tick 数ではなくフレーム数に比例する（速度を上げても増えない） |
| 昼夜と睡眠の不整合が残る | 3.4 の (b) を採る。(a) は「表現が嘘をつく」ことを承知で選ぶ場合に限る |

**非目標**:

- **季節による日長の変化**（3.2）
- **光源としての焚き火・松明**（魔力灯で足りる。増やすなら灯りの意味が薄まってから）
- **視界・索敵の概念**（暗さは表現であって、見える範囲を変えるものではない。索敵はフェーズ4の領域）
- **タイル単位の陰影・法線・動的影**（2Dスプライトの世界に持ち込む価値がない）
- **移動アニメーションの追加フレーム**（歩行4フレームは既にある。足りないのは補間の速さであってフレーム数ではない）
- **経路そのものの滑らか化（斜め移動・曲線）**（4方向グリッド A\* は 7 章の前提。崩すと到達可能性の判定まで波及する）

## 実装メモ（実装後の追記。本文は提案時のまま）

M-1〜M-3・N-1〜N-3 すべて実装済み。実測値は design-notes.md「時間と動き（フェーズ7）」、
現況の要約は design.md 11章。提案からの差分は4点、いずれも**実測が理由**:

- **`stepProgress` は移行不要のオプショナルフィールドにした**（2.3 は「移行は0を補うだけ」と
  書いたが、`LogEntry.kind` と同じ「無ければ0と読む」形にすれば `schemaVersion` を動かす必要が
  ない。歩の端数は次の歩へ持ち越す——リセットすると 1.15 倍の荷が 1.5 倍に化ける）
- **しきい値乗数だけでは睡眠は夜に寄らなかった**（3.4 の (b) そのままでは不足）。数値モデルと
  実シミュレーション両方で計測: 睡眠サイクルは約21時間で時計とずれ続け、乗数をどう振っても
  夜間開始は最大50%（一様で42%）。**「夜の眠りは夜明けまで続く」を最小の錨として追加**
  （`runSleeping` の覚醒判定に1行。空腹 85 超では夜中でも起きる——飢えたまま行儀よく
  寝続ける入植者を作らないため）
- **睡眠の夕方の傾斜は画面の日暮れ（17〜19時）より遅い20〜22時に置いた**。画面と同じ位置に
  置くと就寝が17時台に固定され、夜明けまでの拘束で労働が1日あたり約4時間消え、
  「冬に備えた植民地が冬を越す」季節テストが餓死で落ちた（実測）。20〜22時なら就寝は
  約20:40、睡眠は約8時間に収まる
- **完成音ならぬ灯りの表現は「穴」ではなく加算の光**（3.3 の「減算する円」）。全面オーバーレイに
  穴を開けるにはレンダーテクスチャが要るが、放射グラデーションのスプライトを加算合成で
  重ねれば1枚で済み、見た目も柔らかい。グラデーションはコードから生成（アセット0バイト）

計測（3シード×8日、最初の3日は過渡として除外）: **睡眠 tick の夜間（19〜05時）比率は
0.638〜0.671**。一様なら 0.417 なので、明確に夜へ寄っている。就寝の強制は無い——
夜勤（夜に働き続ける）も昼寝（限界が来れば昼でも寝る）も引き続き起きる。
