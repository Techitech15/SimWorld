## 1. 位置づけ — 効かせ先は3つあり、欠けているのは気温だけ

装備は「服」と「武器」の2つだが、**効かせ先で見ると3つ**に割れ、それぞれ前提が違う。

| 装備 | 効かせたい先 | その先の状態 |
| --- | --- | --- |
| 狩猟具・作業具 | 狩猟と作業 | **実装済み**。`HUNT_RANGE` も `WORK_TICKS` も既にある（2 章） |
| 戦闘武器・防具 | 戦闘 | **実装済み**（フェーズ4。`src/core/raid.ts`、襲撃・民兵・タレット） |
| 防寒着 | 気温 | **未実装**。[design.md](design.md) 9 章の非実装リストに「天候・気温管理（季節はあるが気温は無い）」とある |

本書の初稿は戦闘が未実装であることを前提に「武器には狩猟という抜け道がある」と論じていた。
フェーズ4が実装されたいま、**抜け道は抜け道ではなくなり、単に2つある入口の片方**になった。
2 章の狩猟の議論はそのまま有効で（狩猟具は戦闘とは独立に意味を持つ）、
変わったのは「戦闘武器を待たなくてよい」ではなく「**戦闘武器も今すぐ設計できる**」のほうである。

したがって本フェーズは**3つの部分**に割れ、欠けている前提を持つのは防寒着だけになる。

| 部分 | 前提 | いつ着手できるか |
| --- | --- | --- |
| 狩猟具（弓・槍）と作業具 | 作業台（[design-next.md](design-next.md) 提案3） | **作業台が入ればすぐ** |
| 戦闘武器・防具 | 作業台＋フェーズ4（**どちらも条件を満たしうる**） | 同上。ただし民兵の実装を読んでから数値を決める |
| 防寒着 | 気温、または 3 章の代案 | 3 章の (a) を採るなら気温は要らない |

## 2. 武器は戦闘を待たずに意味を持つ（狩猟）

戦闘（フェーズ4）は実装されたが、**戦闘だけが武器の使い道ではない** —— この世界には狩猟がある。
そして狩猟具のほうが、戦闘武器より先に設計できる（襲撃は稀な出来事だが、狩猟は毎日の仕事だから）。

`HUNT_RANGE = 5` という射程が既に存在し、`WORK_TICKS.hunt = 60` という作業時間もある。
つまり**狩猟は既に「遠くから、時間をかけて仕留める」行為としてモデル化されている**。
装備はここに乗るだけでよく、戦闘機構を1つも要求しない。

| 装備 | 曲げる既存の数値 | 効果（出発点） |
| --- | --- | --- |
| 狩猟弓 | `HUNT_RANGE` | 5 → 8。遠くから狙える＝猪の突進（`BOAR_CHARGE_RANGE = 6`）の外に立てる |
| 狩猟槍 | `WORK_TICKS.hunt` | 0.75 倍。速いが射程は伸びない |
| 作業具（斧・鶴嘴） | `WORK_TICKS.chop` / `.mine` | 0.8 倍。特性・スキルと同じく既存の数値への乗数 |

**弓と猪の関係が、この設計の核心である。** 現在の猪は「体力80、狩人に突進する、射程6」で、
`design-notes` が「狩猟は遠距離なので完全に無リスクだった」ことへの答えとして入れたもの。
射程8の弓は**その答えに対するプレイヤー側の答え**になる —— 装備を整えれば猪を安全に狩れる。
新しい脅威を足すのではなく、**既にある脅威に対処する手段**を足す形になっている。

防具はここでは入れない。狩猟で受ける傷は猪の突進だけで、それは弓（射程）で避けるほうが筋がよい。
防具が意味を持つのは「避けられない攻撃」があるときで、それは襲撃である —— フェーズ4が実装された以上
**その相手は既に存在する**ので、防具は 7 章の E-6 として実際の段階になった（初稿では「本書では扱わない」
としていた）。

## 3. 服が意味を持つには何が要るか

服の役割は普通「寒さを防ぐ」だが、**この世界に気温は無い**。季節はあり、冬は作物と草が止まるが、
それは気温ではなく成長率の表である。気温を入れるとタイルごとの温度場・断熱・部屋の判定が芋づるで要り、
[design-phase6-space.md](design-phase6-space.md) と [design-next.md](design-next.md) の両方が
それを非目標に置いている。

**気温を入れずに服へ意味を持たせる道が2つある。**

| 案 | 内容 | 評価 |
| --- | --- | --- |
| (a) 冬に直接効かせる | 冬のあいだ、防寒着を着ていない入植者の気分・作業速度に負の乗数 | 気温を作らずに済む。季節は既に全員が見ている値 |
| (b) 気分だけに効かせる | 良い服は気分 +、ぼろは気分 − | いちばん安いが、**着る理由が弱い** |

**推奨は (a)。** 冬は既にこの植民地で最も厳しい季節で（食料が 1506 → 934 まで落ちる、
草も作物も止まる）、そこに「備えられる」項目が1つ増えるのは、季節の意味を強める方向に働く。
しかも実装は `seasonOf(tick) === 'winter'` の分岐1つで、気温のモデルを1行も要求しない。

(b) は (a) に含めてよい（防寒着は冬に効き、良い服は年中わずかに気分を上げる）。

## 4. データモデル

本編 4 章の原則（メソッドを持たない、参照は ID、`Record` と配列とプリミティブのみ）を踏襲する。

```typescript
type EquipmentId = string;

type EquipmentKind = 'huntingBow' | 'huntingSpear' | 'axe' | 'pickaxe' | 'warmCoat';
/** 1体につき1つずつ。手は武器と道具を兼ねる（持ち替えは仕事に応じて自動） */
type EquipmentSlot = 'hand' | 'body';

interface Equipment {
  id: EquipmentId;
  kind: EquipmentKind;
  /** 装備している入植者。倉にあるときは null */
  wornBy: ColonistId | null;
  /** 倉・地面にあるときの位置。装備中は null */
  position: Vector2 | null;
  /** 0..1。使うほど減り、0 で壊れて消える */
  condition: number;
}
```

`GameState` への追加は **1つだけ**。

```typescript
interface GameState {
  // ...既存に加えて
  equipment: Record<EquipmentId, Equipment>;
}
```

**`Colonist` に装備品の一覧を持たせない。** `wornBy` の一方向だけにして、
「誰が何を着ているか」は毎回導出する。両方に持たせると**必ずずれる**（
`design-notes.md` が「保存された導出値は、それが説明している対象と食い違いうる」として
マナネットワークで学んだのと同じ形）。

**種類ごとの性能はテーブルに置き、`Equipment` には持たせない。** 建築コストや `MANA_DRAW` と同じ理由で、
性能は「種類の性質」であって「個体の性質」ではない。個体が持つのは `condition` だけ。

**`ResourceType` は増やさない。** 装備は資源ではなく個体を持つ物なので、`items` ではなく
`equipment` に載る。倉に置くときは位置を持ち、既存の運搬ジョブ……**は使えない**（
`haul` は `ResourceType` のスタックを運ぶ）。ここは 7 章の段階 E-1 で扱う。

## 5. 作る手段 — 作業台への依存

装備はどこから来るのか。選択肢は3つあり、**作る**を採る。

| 案 | 評価 |
| --- | --- |
| 交易で買う | フェーズ5（未実装）に依存する。しかも買うだけだと作る楽しみが無い |
| 初期装備として配る | 一度きりで、以後の意思決定にならない |
| **作業台で作る** | [design-next.md](design-next.md) 提案3 が既に `workbench` と `craft` ジョブを提案している |

したがって本フェーズは**提案3（作業台と調理）を前提にする**。提案3 は
「1レシピで機構が正しいことを確かめてから増やす」と書いていて、装備はその2レシピ目以降になる。
逆に言えば、**装備のために新しい生産機構を作る必要は無い**。

材料は既存の4資源で足りる（弓＝木材、槍＝木材＋石、斧・鶴嘴＝木材＋石、防寒着＝食料……ではない）。
**防寒着だけは材料が無い。** 皮革は design-phase2.5-animals.md が非目標に置いている。
これは 8 章で正直に扱う。

## 6. バランス初期値

**すべて未実測の出発点。**

| 装備 | 材料 | 効果 | 耐久 |
| --- | --- | --- | --- |
| 狩猟弓 | 木材 25 | `HUNT_RANGE` 5 → 8 | 狩猟 40 回 |
| 狩猟槍 | 木材 15・石 10 | 狩猟の作業時間 0.75 倍 | 狩猟 60 回 |
| 斧 | 木材 10・石 15 | 伐採 0.8 倍 | 伐採 120 回 |
| 鶴嘴 | 木材 10・石 20 | 採掘 0.8 倍 | 採掘 100 回 |
| 防寒着 | （未定。8 章） | 冬の気分と作業速度の負を打ち消す | 1年 |

**装備は特性・スキルと掛け算で合成する。** レベル10の木こり（1.8倍）が斧（0.8倍）を持てば
`WORK_TICKS.chop` に対して実効 0.44 倍。特性が既にこの形なので、合成の規則を新しく決める必要はない。

**壊れる。** 耐久を入れるのは、装備が「一度作れば終わり」の一回性の買い物にならないようにするため。
壊れたら消え、作り直す仕事が生まれる —— これは畑・修理と同じ「回り続ける仕事」の形。

## 7. 段階と「動いたと言える条件」

| 段階 | 内容 | 前提 | 動いたと言える条件 |
| --- | --- | --- | --- |
| **E-1** | `Equipment` 型・倉への保管・装備と解除 | 提案3（作業台） | 作った道具が倉に入り、入植者が装備し、セーブを往復しても誰が何を持っているか変わらない |
| **E-2** | 作業具（斧・鶴嘴） | E-1 | 斧を持った入植者の伐採が実際に速い。スキルと掛け算になる。**装備ゼロなら導入前と一致する** |
| **E-3** | 狩猟具（弓・槍） | E-2 | 弓を持つと猪の突進の外から狩れる。槍は速いが射程は伸びない |
| **E-4** | 耐久と作り直し | E-3 | 使うほど減り、0 で消え、作り直す仕事が自動で生まれる |
| **E-5** | 防寒着 | 3 章の (a) と、材料の決着（8 章） | 冬に防寒着を着た入植者と着ていない入植者で、気分と作業速度に差が出る |
| **E-6** | 戦闘武器・防具 | E-1 ＋ フェーズ4（実装済み） | 装備した民兵が襲撃で実際に有利になる。装備ゼロなら現在の襲撃と同じ結果になる |

### テスト方針

- **E-1**: `wornBy` と「誰が何を持っているか」の導出が常に一致する（`chaos.test.ts` の不変条件に1つ足す）
- **E-1**: 入植者が死んだとき、装備が取り残されない（`death.test.ts` と同じ形の後始末）
- **E-2**: 装備ゼロの植民地の1年計測が、導入前と一致する
- **E-3**: 弓を持った狩人が `BOAR_CHARGE_RANGE` の外から仕留められること
- **E-4**: 耐久0で装備が消え、同じ道具を作る仕事が生成されること（**黙って消えないこと**）
- **E-5**: 冬にだけ差が出て、他の季節では差が出ないこと

## 8. リスクと非目標

| リスク | 対策 |
| --- | --- |
| 前提（作業台・気温）が揃わないまま着手する | 段階ごとに前提を明記した（7 章）。E-1〜E-4 と E-6 は作業台だけに依存し、気温を要するのは E-5 のみ |
| **防寒着の材料が無い** | 皮革は design-phase2.5-animals.md の非目標。布・羊毛を入れるか、E-5 を保留するかは E-5 着手時に決める。**本書では未決のままにしておく**（決めた顔をしないほうがよい） |
| 装備が「作れば必ず得」になり、選択にならない | 材料と耐久が代償になる。斧を作る木材は壁にも使える |
| `Colonist` と `Equipment` の双方向参照でずれる | 参照は `wornBy` の一方向だけ（4 章） |
| スキル・特性・装備の三重の乗数で速度が壊れる | 合成は掛け算で統一し、`ColonistDetail` の実効速度表示（既存）に装備の寄与も出す |

**非目標**:

- **気温・断熱・部屋の判定**（3 章。服は季節で直接効かせる）
- **部位ごとの装備・装備スロットの拡張**（`hand` と `body` の2つで止める）
- **品質（業物・粗悪）**（`condition` だけを持つ。品質を入れるとスキルとの交差で組み合わせが増える）
- **命中・射線・部位判定**（フェーズ4の戦闘は実装済みだが、その解像度を上げるのは別の話。装備は既存の戦闘の数値に乗るだけにする）
- **皮革・毛皮の加工チェーン**（design-phase2.5-animals.md の非目標のまま）
- **装備の交易**（フェーズ5の商人は既存4資源を扱う。装備の売買はどちらも実装されてから）

## 実装メモ（実装後の追記。本文は提案時のまま）

E-1〜E-4・E-6 実装済み。**E-5（防寒着）は保留のまま**——8章が「決めた顔をしないほうがよい」と
残した材料未決を、実装でも未決のまま残した（布・皮革を入れるかは別途）。決め手と実測は
design-notes.md「装備（フェーズ8）」、現況は design.md 11章。提案からの差分は3点:

- **装備は倉庫へ運ばない。** E-1 は「倉への保管」を挙げたが、`haul` が使えない（4章の指摘どおり）
  以上、装備専用の運搬チェーンを作ることになる。代わりに**手の空いた入植者が直接拾いに行く**
  （仕事も欲求も無いときだけ、最寄りの誰も持たない装備へ歩いて装備する。予約は持たず、
  競合は先着で解決）。装備は作られた場所・落ちた場所に置かれ、それで足りている
- **種類の表から防寒着が抜け、剣と鉄の鎧が入った**（E-6 の材料は鉄が埋めた。剣=木5+鉄8、
  鎧=鉄15）。斧・鶴嘴・弓・槍は6章の表のまま
- **作り直しの注文先は「最初に見つかった作業台」**（E-4）。最寄り探索はしていない——
  作業台が複数ある植民地はまだ実在せず、注文はどの台でも同じ列に並ぶ

機構は全て既存への乗数で、`putInWork`（スキル・気分と同じ場所）に道具、`strikeColonist` に鎧、
民兵の一撃に剣、`HUNT_RANGE` に弓が掛かる。`GameState` への追加は `equipment` レコード1つ
（`schemaVersion` 23→24、空レコードを補うだけ）と `Building.craftOrders`（オプショナル）。
