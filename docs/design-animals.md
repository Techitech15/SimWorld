## 1. 位置づけと設計原則との整合

本編 11 章のロードマップは フェーズ2=魔力インフラ → 3=物語生成 → 4=防衛 であり、**動物はどこにも存在しない**。
そのため生物レイヤーは新たに**フェーズ2.5**として定義し、魔力インフラ（フェーズ2）とは独立に着手できるものとする。

コアの魅力（1. 最適化パズル、2. 物語生成、3. 防衛と危機管理）に対しては次の位置づけになる。

| 要素           | 効く軸                         | 既存システムとの関係                                     |
| -------------- | ------------------------------ | -------------------------------------------------------- |
| 野生動物＋狩猟 | 1（食料チェーンに第2の供給源） | 「指定 → ジョブ → 資源が落ちる」型。伐採・採掘と**同型** |
| 手懐け＋牧畜   | 1（頭数と牧草面積の最適化）    | 「時間で育ち収穫する」型。畑と**同型**                   |
| 捕食者         | 3（外部からの圧力）            | 新規。フェーズ4の領域に最小限だけ踏み込む                |

**本編の設計原則との整合**:

- 原則1（データとロジックの分離）: 追加する型はすべてプレーンデータ・ID 参照とし、`JSON.stringify` で保存できる状態を維持する
- 原則2（シミュレーションと描画の分離）: 動物は `GameState.animals` に載るだけで、描画は既存の購読モデルのまま
- 原則3（MVP の範囲を増やさない）: MVP は既に完成しているため本レイヤーは MVP の外。ただし後述する **HP と死亡** は
  本編 9 章が明示的に除外した領域なので、最小モデルに限定し、限界を 11 章に明記する

### 意図的な逸脱: HP と死亡

捕食者を入れる以上、「襲われても何も起きない」では脅威にならないため、HP と死亡を導入せざるを得ない。
本編 9 章の「含まないもの: 健康画面／怪我／病気」に対する逸脱であり、次の範囲に限定する。

- 部位・怪我の種類・病気・治療ジョブは**入れない**。`health: number`（0..100）ひとつだけ
- 回復は休息・睡眠中の緩やかな自然回復のみ
- 0 になったら死亡し、エンティティを除去してログに残す。墓・追悼・mood への波及は**フェーズ3に温存**

## 2. データモデル

本編 4 章の原則（メソッドを持たない、参照は ID、`Record` と配列とプリミティブのみ）を踏襲する。

```typescript
type AnimalId = string;

type AnimalSpecies = 'deer' | 'boar' | 'chicken' | 'wolf';
type AnimalDiet = 'herbivore' | 'omnivore' | 'carnivore';

/** 動物の振る舞い。Colonist.activity と同じく「ジョブ系の外側」に置く */
type AnimalActivity =
  | { kind: 'idle' }
  | { kind: 'wander'; targetTileId: TileId }
  | { kind: 'grazing'; ticksRemaining: number }
  | { kind: 'fleeing'; fromEntityId: string; untilTick: number }
  | { kind: 'stalking'; targetEntityId: string } // 捕食者が獲物へ接近中
  | { kind: 'attacking'; targetEntityId: string; nextBiteTick: number };

interface Animal {
  id: AnimalId;
  species: AnimalSpecies;
  position: Vector2;
  /** 追跡・帰巣のときだけ持つ。徘徊・逃走では null（7章の性能方針を参照） */
  path: Vector2[] | null;
  pathExpiresAtTick: number | null;
  hunger: number; // 0(満腹)〜100 直線減衰。入植者と同じ方式
  health: number; // 0..100
  bornAtTick: number; // 成体判定と繁殖条件に使う
  tame: boolean;
  pastureZoneId: ZoneId | null; // tame のときだけ非 null
  activity: AnimalActivity;
  reservedByJobId: JobId | null; // 狩猟・手懐けの対象予約（6章の予約機構に載る）
  gestationUntilTick: number | null;
}
```

`GameState` への追加:

```typescript
interface GameState {
  // ...既存に加えて
  animals: Record<AnimalId, Animal>;
}
```

既存型への追加（すべて `[ext]` コメントを付す。本編 4 章の追加欄と同じ運用）:

| 型          | 追加                                         | 理由                                                                    |
| ----------- | -------------------------------------------- | ----------------------------------------------------------------------- |
| `Zone.type` | `'pasture'` を追加                           | 放牧範囲。既存の貯蔵ゾーンと同じ「タイル集合」表現をそのまま使う        |
| `Tile`      | `forage: number`（0..1、草地のみ意味を持つ） | 放牧圧と回復を 1 フィールドで表す。過放牧のパズルはこの値だけで成立する |
| `Colonist`  | `health: number`                             | 1章の逸脱の範囲                                                         |

### 資源型は増やさない

肉・卵・乳はすべて既存の `food` として落とす。`ResourceType` を増やすと貯蔵・運搬・食事・資源一覧 UI の
全経路に波及するのに対し、数量だけ増える形なら既存チェーンが**無改造で機能する**。

見た目を分けたくなった場合の代替案は `Item.variant?: string`（描画とツールチップだけが参照する表示用タグ）で、
シミュレーション側のロジックは `type` だけを見る、という分離にする。この判断は後から入れても破壊的にならない。

## 3. ジョブ種別の追加

本編 6 章のライフサイクル（生成 → 候補フィルタ → 予約 → 実行 → 解放）は**一切変更しない**。
`JobType` に 2 種だけ追加し、仕事優先度表は 5 列 → 7 列になる。

| 追加     | 内容                                                           | 既存のどれと同型か                   |
| -------- | -------------------------------------------------------------- | ------------------------------------ |
| `hunt`   | 指定した野生動物を追跡して仕留め、その場に食料スタックを落とす | `chop`（対象を消費して資源を落とす） |
| `handle` | 手懐け・家畜の世話・屠殺                                       | `farm`（対象に対する反復作業）       |

RimWorld も Hunting と Handling は別の仕事列なので、この 2 列という粒度は原典に沿っている。
屠殺を独立列にしないのは、MVP に調理・作業台の概念がなく、列だけ増えても操作の解像度が上がらないため。

### 動く対象を扱うための最小の変更

既存ジョブの対象は静止物（タイル・建築・アイテム）だが、動物は動く。差分は次の 2 点に閉じる。

1. `jobWorkSite()` が動物ジョブのときは**その時点の動物の位置**を返す（`src/core/jobs/assign.ts`）
2. `advanceTowards()` の目的地が毎 tick 変わるため、経路の再計算頻度に上限を設ける（7 章）

予約は既存の `reservations[animalId]` をそのまま使う。動物が逃走・死亡した場合は
`isJobStillValid()` に動物の存在チェックを足すだけで、既存の "target disappeared" → cancel 経路に乗る。

### 狩猟の結果物

仕留めた瞬間に、その場へ食料スタック（種別ごとの量）を落とす。死体エンティティと屠殺台は**作らない**。
これにより既存の運搬ジョブが自動的に回収し、貯蔵まで運ぶ。
「死体 → 屠殺台 → 肉」という原典寄りのチェーンは、作業台の概念を入れる段階で再検討する。

## 4. 生態シミュレーション

新規 `src/core/animals.ts` に置き、tick パイプライン（`src/core/simulation.ts`）へ次の位置で差し込む。

```
growCrops → regrowForage → runNeeds → runMoveOrders → runAnimals
→ runJobGenerator → runAssignment → runExecution → cleanupJobs → cleanupDead
```

`runAnimals` は動物ごとに「空腹・加齢の進行 → 振る舞いの遷移 → 移動 → 捕食/繁殖/産出の判定」を 1 tick 進める。
`cleanupDead` は `health <= 0` のエンティティを除去し、ログに残す（動物と入植者で共通）。

| 振る舞い       | 遷移条件                                     | 内容                                                        |
| -------------- | -------------------------------------------- | ----------------------------------------------------------- |
| 徘徊           | 既定                                         | 隣接1マスへのランダムウォーク。A\* を使わない               |
| 採食           | `hunger > 40` かつ足元が `forage > 0` の草地 | `forage` を消費して `hunger` を回復。家畜は牧場内でのみ行う |
| 逃走           | 隣接〜2マスに捕食者、または狩猟対象にされた  | 脅威と反対方向へ 1 マス。A\* を使わない                     |
| 接近（捕食者） | `hunger > 閾値` かつ獲物が視界内             | 獲物へ A\* で接近（頻度制限あり）                           |
| 攻撃（捕食者） | 獲物と隣接                                   | 周期的にダメージ。満腹または被ダメージ閾値で撤退            |
| 帰巣（家畜）   | 牧場外にいる                                 | 牧場の最寄りタイルへ A\*                                    |

**繁殖**: 同じ牧場に成体2頭以上・両方が満腹 → `gestationUntilTick` を設定 → 満了で 1 頭出産。
頭数上限は牧場の面積から算出し、上限に達したら妊娠しない。

**産出**: 家畜は周期的に牧場内へ食料アイテムを落とす。既存の運搬ジョブが自動で拾うため、新規ジョブは不要。

## 5. 捕食者と入植者の反応

- 捕食者は獲物を **野生の草食獣 > 家畜 > 入植者** の順に選ぶ。入植者が最初の標的になりにくいことで理不尽を減らす
- 攻撃された入植者は `activity: fleeing` になり、最寄りのベッド／壁で囲まれた領域へ退避する。**反撃はしない**
  （戦闘は本編フェーズ4の領域であり、ここで前倒しすると武器・命中・射線まで芋づる式に必要になる）
- プレイヤーの対抗手段は「捕食者に `hunt` を指定する」こと。**既存の仕組みだけで対抗策が成立する**のが本設計の要点
- 入植者の `health` は休息・睡眠中に緩やかに回復する。0 で死亡

UI は既存資産の範囲で完結させる。

- `ColonistPanel` に health バーを 1 本追加（空腹・睡眠と同じ `NeedBar` を色違いで再利用）
- 襲撃・死亡・出産・過放牧の警告は既存の `EventLog` に流す

## 6. バランス初期値

60×60 マップ・入植者3人を前提とした暫定値。実測して調整する。

### 種別

| 種         | 食性 | 初期数 | 食料産出 | 手懐け成功率 | 備考                                      |
| ---------- | ---- | ------ | -------- | ------------ | ----------------------------------------- |
| 鹿 deer    | 草食 | 6      | 45       | 0.40         | 3 tick に 1 マス。狼（2 tick）より遅い    |
| 猪 boar    | 雑食 | 4      | 60       | 0.30         | 手懐け失敗時に威嚇して逃げる              |
| 鶏 chicken | 草食 | 8      | 12       | 0.60         | 家畜化すると 1,500 tick ごとに卵（食料6） |
| 狼 wolf    | 肉食 | 2      | 30       | 手懐け不可   | 捕食者                                    |

### 数値

| 項目           | 値                        | 根拠・意図                                      |
| -------------- | ------------------------- | ----------------------------------------------- |
| 動物の空腹進行 | 100 / 3,600 tick          | 入植者（100 / 2,400 tick）より緩やか            |
| 採食1回の回復  | 35                        | 1日に2〜3回の採食で足りる                       |
| `forage` 消費  | 採食1回で 0.35            | 1タイルが3回分。頭数×面積の見積もりが立てやすい |
| `forage` 回復  | 1 / 3,000 tick            | 1日で全快。過放牧すると回復が追いつかない       |
| 狼の狩猟開始   | `hunger >= 60`            | 常時襲ってこない                                |
| 狼の攻撃       | 12 ダメージ / 10 tick     | 入植者は約 80 tick 耐える。逃走が間に合う設計   |
| 狼の撤退       | `health <= 40` または満腹 | 一方的に殴られ続ける展開を防ぐ                  |
| 狩猟の作業時間 | 60 tick（接近後）         | 伐採40・採掘60 と同水準                         |
| 妊娠期間       | 3,000 tick（1日）         |                                                 |
| 頭数上限       | 牧場タイル数 ÷ 4          | 上限で自動的に頭打ちになる                      |

### 序盤の理不尽を避ける制約

- 捕食者は**2日目以降**に出現する（初日は生成しない）
- 捕食者の初期位置は森タイルに限定し、キャンプ中心から一定距離以上離す
- マップ上の捕食者は上限2頭。減ったら森の端から補充される

## 7. 性能方針

本編 7 章は「A* の再計算トリガーは目的地変更と地形変更の 2 つだけ」という制約で成立している。
動物 20〜40 体が毎 tick A* を走らせるとこの前提が壊れるため、次の方針を守る。

- **徘徊・逃走・採食は A\* を使わない**（隣接1マスの判断のみ）。動物の大半は常にこの状態にある
- A\* を使うのは**追跡と帰巣だけ**。1 tick あたりの実行本数に上限を設ける
  （既存の `CANDIDATE_PATH_ATTEMPTS` と同じ考え方）
- 動物の経路は **PathIndex に登録しない**。代わりに `pathExpiresAtTick` で最大 N tick で失効させる。
  地形変更時の厳密な無効化より失効のほうが安く、動物には十分（壁が建って行けなくなっても、
  次の失効時に別経路を引き直せばよい）
- 捕食者の獲物探索は全走査ではなく、視界半径内のタイルに限定する

「動物が増えても入植者の経路探索コストが増えない」ことを性能テストで担保する（10 章）。

## 8. セーブ互換

`schemaVersion` を 1 → 2 に上げ、`migrations[1]` を実装する（`src/persistence/saveFile.ts`）。
既存のマイグレーション機構にとっての初仕事になる。

補うもの: `animals: {}`、各タイルの `forage`（草地は 1、それ以外は 0）、各入植者の `health: 100`。

既存の「移行できないほど古いセーブはロードを拒否する」テストはそのまま通る。
`Animal` は他のエンティティと同じくプレーンデータなので、保存は引き続き `JSON.stringify` だけで完結する。

## 10. 実装フェーズと「動いたと言える条件」

本編 10 章と同じく、各段階に受け入れ条件を置く。段階ごとにコミット・テストを完結させる。

| 段階 | 内容                                             | 動いたと言える条件                                                           |
| ---- | ------------------------------------------------ | ---------------------------------------------------------------------------- |
| A    | `Animal` 型・徘徊・採食・`forage`・`hunt` ジョブ | 鹿を指定すると入植者が追跡して仕留め、落ちた肉が貯蔵ゾーンまで運ばれる       |
| B    | 捕食者・`health`・逃走・死亡・ログ               | 狼が野生動物を襲い、入植者は逃げる。狩猟指定で排除でき、放置しても全滅しない |
| C    | 手懐け・牧場ゾーン・`handle` ジョブ              | 手懐けた家畜が牧場内に留まり草を食べる。過放牧すると `forage` が枯れて痩せる |
| D    | 繁殖・産出・頭数上限                             | 無操作で家畜が増えて食料を産み、上限で頭打ちになる                           |

### テスト方針（既存のヘッドレステストに追加）

- **A**: 狩猟ジョブの予約排他（2人が同じ鹿を追わない）。既存 `jobs.test.ts` の二重予約検査をそのまま流用
- **A**: 仕留めた食料が貯蔵まで到達する（運搬チェーンとの結合）
- **B**: 狼が獲物を仕留めた後に狩りをやめる／入植者が逃走して生存する／数日放置で全滅しない
- **C**: `forage` の消費と回復が釣り合う頭数では痩せず、超過すると痩せる
- **D**: 頭数が上限で頭打ちになる（無限増殖しない）
- **性能**: 動物40体でも 1 tick あたりの A\* 実行回数が上限以下に収まる
- **セーブ**: v1 のセーブが v2 へ移行でき、移行後に tick を進めても壊れない

## 11. リスクと非目標

| リスク                                           | 対策                                  |
| ------------------------------------------------ | ------------------------------------- |
| 生態系の暴走（増えすぎ → 草の枯渇 → 餓死ループ） | 頭数上限、`forage` の枯渇をログで警告 |
| 序盤の理不尽（初日に狼で詰む）                   | 出現条件（2日目以降・森・距離）で回避 |
| 動物の増加で入植者の思考が遅くなる               | 7章の A\* 制限。性能テストで担保      |
| 捕食者に対して何もできない                       | 既存の狩猟ジョブが対抗手段になる設計  |
| スコープ膨張                                     | 下記の非目標を守る                    |

**非目標（この段階では入れない）**:

- 屠殺台・皮革・毛皮などの二次加工チェーン（作業台の概念が要る）
- 調教スキル・動物ごとの訓練段階（スキルはフェーズ3）
- 動物の mood・懐き度・ペットとしての絆（物語生成はフェーズ3）
- 入植者の反撃・武器・射線（戦闘はフェーズ4）
- 部位ごとの怪我・病気・治療ジョブ（本編 9 章の除外を維持）

## 12. 実装メモ（設計案からの差分）

段階 A〜D をすべて実装したうえで、実測して変えた点と、設計案どおりにいかなかった点を残す。
数値の出典は `src/core/constants.ts`、挙動の検証は `src/core/animals.test.ts`（11件）と
`src/core/survival.test.ts` の4日間無操作テスト。

### 実際の tick パイプライン

`regrowForage` は独立した段ではなく `runAnimals` の先頭に入った。`cleanupDead` も独立させず、
死亡はその場（`killAnimal` / `damageColonist`）で処理してログに残す。

```
growCrops → runNeeds → runMoveOrders → runAnimals → runFleeing → healColonists
→ runJobGenerator → runAssignment → runExecution → cleanupJobs
```

`runFleeing` が `runAnimals` の直後に来るのは、捕食者が動いた結果を同じ tick のうちに
入植者の逃走へ反映するため。ジョブ割り当てはそのあとなので、逃げている入植者に仕事は回らない。

### 実測して足した4つの調整

いずれも「狼が入植者を確実に殺してしまう」または「狼が誰も捕まえられない」のどちらかに倒れたための修正。

| 追加                                          | 理由                                                                                              |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 接触したその tick で噛む                      | 「隣接した次の tick に噛む」だと、逃げる相手は必ず先に離れてしまい捕食が一度も成立しなかった      |
| 逃走タイマーは捕食者が近い間は減らない        | 120 tick で作業に戻ると狼に噛まれ直し、消耗戦で必ず入植者が死んだ                                 |
| 逃走はニーズ（食事・睡眠）より優先            | 狼に追われている最中にベッドへ寝に行って食べられていた                                            |
| 追跡を諦めた捕食者は 600 tick 狩りを再開しない | 諦めた直後に同じ相手を再標的にするため、`PREDATOR_PURSUIT_TICKS` が実質機能していなかった          |

そのために `Animal.huntCooldownUntilTick` を1フィールドだけ追加した。

逃走の1歩は「脅威から最も遠ざかる隣接1マス」を4方向から選ぶ。設計案の「逃走軸に沿って1マス」だと
岩壁を背にした個体が動けずその場で食べられるため、横に逃げられる形にした（`fleeStep`、動物と入植者で共用）。

### 野生動物の補充

野生個体は繁殖しない（繁殖は牧場の家畜のみ）ため、実測すると 8 日で 18 頭が 7 頭まで減り、
獲物を失った狼が入植者だけを狙うようになった。捕食者と同じ方式で、1日1頭ずつ初期数まで
マップ端から補充する（`WILDLIFE_RESPAWN_INTERVAL_TICKS`）。10 日間の無操作実行で個体数が
初期値付近で安定することを確認している。

### 設計案どおりにしなかった点

- **死体スプライトは作らない**: 死体エンティティ自体が無く、仕留めた瞬間に食料スタックへ変わるため
- **狩猟対象は逃げない**: 狩猟は射程5の遠距離作業（`HUNT_RANGE`）なので、追い詰める必要がない。
  逃走のトリガーは捕食者の接近だけ
- **逃走先は「壁で囲まれた領域」ではない**: 退避先の探索は A\* を要するうえ、逃げる先が安全かどうかの
  判定は防衛（フェーズ4）の領域に入る。実装は「脅威から遠ざかる1歩」に留めた
- **鹿は狼より遅い**: 設計案の表では鹿を「逃げ足が速い」としていたが、狼が誰も捕まえられなくなるため、
  最速は狼（2 tick/マス）にした。鹿・猪は3、鶏は4

### この設計案のあとに足したもの

段階 A〜D の完成後、季節と扉が入ったことで生態レイヤーに足りなくなった穴を順に埋めた。

| 追加 | 理由 |
| --- | --- |
| **ウサギ**（5種目） | 既存4種が「そこそこ遅い・そこそこ肉が取れる」の帯に固まっていた。狼と同速・肉10・成体まで1日で、群れの回復がいちばん速い端を埋める |
| **扉は動物が通れない** | 壁＋扉＝囲い。狼を締め出し家畜を留める唯一の手段で、これで初めて壁に用途ができた（`isWalkableByAnimal`） |
| **牧場を複数持てる** | 囲いが成立した以上、離れた2つの囲いは2つの群れ・2つの定員でなければ頭数上限も過放牧警告も無意味になる |
| **飼い葉** | 冬は草が戻らないので、囲った群れがプレイヤーの打つ手なく餓死していた。牧場内の食料スタックを食べる（草が先、飼い葉が後、予約済みは触らない） |
| **家畜の餓死警告** | 柵の裏で静かに餓えるのはログが最も埋めやすい事象なので、アラートに出して現場へ飛べるようにした |
| **猪の反撃** | 狩猟は遠距離なので完全に無リスクだった。体力80の猪だけは狩人に突進する（狼と同じ stalk→bite を再利用）。狙うのは自分を狩っている入植者だけ |
| **攻撃中の表示** | 狼や突進中の猪の頭上に赤い点。どの個体が危険かが見えないと反応できない |

いずれも `Animal` に増えたフィールドは `huntCooldownUntilTick` の1つだけで、残りは既存の
ゾーン・アイテム・タイルの上に載っている。セーブは `schemaVersion` 3。
