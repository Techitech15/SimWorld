## 2. ステータスメッセージの定位置化 — 画面がズレる原因は1行の折返し

### 2.1 原因

TopBar のステータス（「セーブしました」「その場所には建てられません」等）は
`.topbar__status { width: 100% }` で描画される。TopBar は `flex-wrap: wrap` なので、
**幅 100% の要素はヘッダ内に2行目を作る** —— メッセージが出た瞬間にヘッダが1行ぶん高くなり、
その下の盤面・サイドバー全体が押し下がる。メッセージが消えると戻る。これがズレの正体で、
シミュレーションにもレイアウト計算のバグにも関係ない。

### 2.2 設計: ヘッダのサマリの隣の固定スロットに入れる

- TopBar の1行目、**時計・季節サマリの隣に固定幅のステータススロット**を常設する
  （`flex: 1` で余白を使い、`min-width: 0` + 省略記号。空でもスロット自体は存在する）
- メッセージの有無で**高さも折返しも変わらない** —— 出るのは文字だけ
- 長文は省略記号で切り、`title` 属性に全文（ホバーで読める）
- 表示時間・消え方は現状のまま（変えるのは置き場所だけ）

**受け入れ条件**: メッセージの出現・消滅の前後で `app__body` の位置が 1px も動かない
（実ビルドで測る）。両言語の代表的な長文メッセージが省略されつつホバーで全文読める。

## 3. オーバーレイの折り畳み — 資源・ミニマップ・選択枠

フェーズ6 は右サイドバーのパネル群に `Fold`（開閉状態は `localStorage`、`GameState` に入れない）を
入れたが、**ビューポート上のオーバーレイ（左上: 資源＋アラート、右上: ミニマップ）には
入れなかった**。盤面を広く見たい局面で、この2つが常に地図の角を占有している。

- 左上（資源）・右上（ミニマップ）・選択枠（4 章でビューポートに来る）に **`Fold` をそのまま適用**する。
  新しい開閉機構は作らない —— 既にあるものの適用範囲を広げるだけ
- 畳んだ状態は見出しチップ1行（クリックで開く）。アラートは**畳みの対象外** ——
  「プレイヤーに見えない失敗を作らない」ため、危機は畳んだ資源パネルの外に出る（現状の
  `AlertPanel` が資源と別コンポーネントなので、資源だけを畳めば済む）
- 開閉状態のキーは既存の `usePanelFold` の体系に乗せる

**受け入れ条件**: 資源・ミニマップ・選択枠が個別に畳め、再訪時に状態が残る／
畳んでいてもアラートは常に見える／畳み・展開で盤面のパン・ズームが乱れない。

## 4. 選択枠をビューポートへ — フェーズ6の「目は地図、答えは右端」の完了形

フェーズ6 は「目は地図を見ているのに答えは右端に出る」を問題にし、選択の結果を
選択の近くに出す方針を書いた。現状の `SelectionFrame`（選択タイル詳細＋入植者詳細＋動物詳細）は
**まだ右サイドバーの最上段にある**。

- `SelectionFrame` をビューポート内のオーバーレイ（**左下**を出発点にする。左上=資源、
  右上=ミニマップと被らない位置）へ移す。`Fold` 付き（3 章）
- 右サイドバーからは選択枠を消す。サイドバーは「植民地全体を見る場所」（入植者一覧・
  仕事表・動物・ログ）に純化され、「いま選んでいるもの」は盤面の上に出る
- 何も選んでいないときは（現状どおり）何も描画しない —— 空でも場所を取らない
- 幅は左上オーバーレイと同じ体系（`max-width` 260px 程度、見積もり）。入植者詳細の
  情報量が収まらない場合は、詳細の長い部分（スキル一覧等）を畳み内に置く

**受け入れ条件**: 入植者・動物・タイルを選ぶと盤面上（左下）に詳細が出て、サイドバーには
出ない／選択解除で消える／畳める／両言語で幅からあふれない（実ビルドで目視）。

## 5. 音 — 実行時合成を第一候補にする

### 5.1 方針: スプライトと同じ規律を音にも使う

このリポジトリの絵は**すべてコードから決定論的に生成**され、外部素材を使わない
（理由: 再生成できる・差分がレビューできる・単一 HTML に同梱できる。design.md 12 章）。
音も同じ規律に乗せる。

**第一候補は Web Audio API による実行時合成**（オシレータ＋エンベロープ＋ノイズで
効果音を都度合成する）。理由は3つ。

1. **アセット 0 バイト。** 単一 HTML ビルド（現在 879 KB）に WAV/OGG を同梱すると
   数百 KB 単位で増える。合成ならコード数 KB で済む
2. **決定論的でレビュー可能。** パラメータ（周波数・減衰・波形）はコードであり、
   スプライト生成と同じくレビューと再現ができる
3. **依存もビルド工程も増えない。** 生成モデルも音声ファイルのパイプラインも要らない

### 5.2 Diffusion Audio（ローカル生成モデル）は保留

指摘にあった「ローカルで Diffusion Audio（Stable Audio 系のモデル）を使う」案は、
**一時保留**とする。理由:

- この開発環境（コンテナ）には GPU が無く、生成モデルの実行・検証ができない
- 生成した音声はファイルとして同梱することになり、単一 HTML の予算（1 の理由）に直撃する
- 実行時合成で「音がある」状態を先に作り、**それで足りないと分かってから**
  高品質アセットの導入を判断する方が、このリポジトリの「測ってから決める」に沿う

再検討の条件も書いておく: 合成 SFX の質が実プレイで不満になり、かつ BGM のような
「合成では作りにくい長い音」が欲しくなった時点で、(a) ローカル生成モデルで作った短いループを
サブセット同梱する、(b) 生成はするが別配布にする、の2案を比較する。

### 5.3 付ける音（出発点）

**効果音は「プレイヤーの操作への応答」と「アラート級の出来事」だけ**に絞る。
全ジョブ・全イベントに音を付けると、10倍速で音の洪水になる。

| 音 | 引き金 | 形（見積もり） |
| --- | --- | --- |
| 配置音 | ブループリント設置・ゾーン指定 | 短いクリック（矩形波 40ms） |
| 完成音 | 建築完了 | 上昇2音（100ms） |
| 警告音 | アラートが `critical` で**増えた**とき | 低い2音（重複発火しない。tick ではなくアラート集合の差分で鳴らす） |
| 襲撃の角笛 | 襲撃開始ログ | 低いノコギリ波（300ms） |
| 研究完了 | テック解禁 | 上昇3音 |
| 取引成立 | 交易成立ログ | コイン風の短音 |

- **BGM は作らない**（非目標。9 章）
- 音量（0〜1）とミュートは `localStorage`。**既定はミュート**とし、初回に
  「音を出す」トグルを TopBar の言語切替の隣に置く —— ブラウザの自動再生制約
  （ユーザー操作前の `AudioContext` は再生できない）とも整合する
- 10倍速では効果音の**間引き**を入れる（同種の音は最短間隔を持つ。見積もり 500ms）

**受け入れ条件**: ミュート既定で一切鳴らない／トグルで鳴り始め、設定が再訪時に残る／
10倍速で1日回しても同種の音が最短間隔を割らない（ヘッドレスで発火回数を数える）／
アラート警告音は同じアラートが出続けている間は再発火しない。

## 6. 夜がまだ明るい問題 — これはフェーズ7の領分

夜になっても盤面の見た目が変わらないのは、**フェーズ7（時間と動き）の昼夜オーバーレイが
未実装**だから。時刻は既にあり（`TICKS_PER_HOUR`、TopBar の時計）、
[design-phase7-time.md](design-phase7-time.md) が全面1枚の色オーバーレイ＋魔力灯の明かり穴＋
夜に寝やすくする補正、まで設計済みで、**新しく設計するものは無い**。

本フェーズには**取り込まない**（フェーズ7の設計案を凍結のまま実装すればよく、
二重に書くと分担の約束が崩れる）。実装順の推奨だけ書く: フェーズ13 の 2〜4 章（画面）と
フェーズ7 は互いに独立なので、**どちらを先にやってもよい**。「夜も明るい」の解消だけが
目的なら、フェーズ7 のうち昼夜オーバーレイと灯りの穴だけを先に入れる切り出しが最も安い。

## 7. データモデル

**`GameState` への追加は無い。** 全部が表示の性質で、シミュレーションは1 tick も変わらない。

| 置き場所 | 中身 |
| --- | --- |
| `localStorage` | オーバーレイ3枠の開閉（既存 `usePanelFold` の体系）・音量・ミュート |
| モジュール定数 | 効果音のパラメータ表（`SFX: Record<SfxName, ...>`。スプライト表と同じ扱い） |
| 辞書（`strings.ts`） | 音トグルのラベル・ツールチップ等。en / ja 両方 |
| セーブ | **変更なし**（`schemaVersion` は動かない） |

音の発火はシミュレーションに書かず、**UI 層が状態変化を購読して鳴らす**
（ログ・アラートの差分を見る）。理由: コアに音の概念を入れると、ヘッドレステストが
音の抑制を知る必要が生まれる。コアは今後も音を知らない。

## 8. 段階と「動いたと言える条件」

| 段階 | 内容 | 動いたと言える条件 |
| --- | --- | --- |
| **A** | ステータスの定位置化（2 章） | メッセージ出現・消滅で `app__body` が 1px も動かない／長文が省略され、ホバーで全文 |
| **B** | オーバーレイの折り畳みと選択枠の移設（3・4 章） | 資源・ミニマップ・選択枠が個別に畳めて記憶される／アラートは常時可視／選択詳細が盤面左下に出てサイドバーから消える |
| **C** | 音（5 章） | ミュート既定・トグルで有効・設定が残る／同種 SFX の最短間隔が守られる／アラート音が再発火しない |

A・B・C は互いに独立で、どの順でも入れられる。いずれも `GameState` に触れないので、
**セーブ互換のリスクはゼロ**。1年計測は tick に触れないため導入前と一致するはず —— 「はず」は
毎回どおり計測で確認する。

## 9. リスクと非目標

| リスク | 対策 |
| --- | --- |
| 選択枠の移設で左下が手狭になる | 位置は出発点。左上（資源）と入れ替える案も比較して実ビルドで決める |
| 合成音が安っぽい | まず操作応答の短音だけに絞る（5.3）。質の判断は鳴らしてから（5.2 の再検討条件） |
| 音の発火漏れ・二重発火 | 発火はログ・アラートの**差分**からのみ。ヘッドレスで発火回数をテストする |
| 畳んだパネルの中で危機が起きて見えない | アラートは畳みの対象外（3 章）。危機は必ず畳みの外に出る |

**非目標（この段階では入れない）**:

- **BGM・環境音ループ**（5.3。まず効果音で「音がある」を作る）
- **Diffusion Audio / 生成モデルによるアセット制作**（5.2 の再検討条件を満たすまで保留）
- **効果音の全イベント網羅**（操作応答＋アラート級のみ）
- **昼夜表現**（フェーズ7の設計案がそのまま有効。二重に設計しない）
- **サイドバー全体の再設計**（フェーズ6で済んでいる。動かすのは選択枠だけ）
- **設定画面**（トグル2つ（言語・音）が TopBar に並ぶだけ。専用画面はまだ要らない）
