## 1. 位置づけ — 「1枚の地図」は守る

[design-next.md](design-next.md) 6 章は「複数マップ」を提案しないものとして挙げてきた。
理由は「『1枚の地図の上の最適化パズル』という土台を変える」。この判断は**撤回しない**。
その上で、フェーズ5が交易で引いた線と同じ線をここでも引く。

| 形 | 何が要るか | 判断 |
| --- | --- | --- |
| プレイ中に複数の地図を持つ（移動・並行シミュレーション） | 地図間の時間・不在中の植民地・帰還の解決 | **採らない**（土台を変える） |
| **生成時に、世界のどこで始めるかを選ぶ** | 生成パラメータの選択画面ひとつ | **採る** |

ワールドマップは**盤面ではなく、生成の文脈**である。プレイが始まれば地図は今までどおり1枚で、
入植者がその外へ出ることはない。ワールドマップが盤面に対してすることは2つだけ ——
生成時に**どんな地形になるか**（バイオーム、3 章）を決め、以後は**外からの圧力の強さと種類**
（部族、4 章）を曲げる。

これは既存の設計の延長にある。外の世界はこれまでも存在した —— 移住者は「食べていける植民地には
人が来る」という圧力として、襲撃者は災厄の1種として、地図の端からやって来る。ただし顔も方角も
無かった。フェーズ11は外の世界に**実体を与えない**まま、**地理と名前**を与える。

## 2. ワールドマップ — 世界は `worldSeed` から導出する

### 2.1 保存するのは「どこを選んだか」だけ

ワールドマップは **16×16 のセル**（見積もり。実装時に見た目で調整）で、各セルはバイオームと
部族の勢力圏を持つ。これらはすべて `worldSeed` から値ノイズ（既存の `valueNoise2D`）で導出する。

**ワールドマップそのものは保存しない。** 原則「導出できるものは保存しない」の適用で、
`GameState` に入るのは選んだセルの座標 `worldCell: {x, y}` **だけ**である。同じ `worldSeed` からは
毎回同じ世界地図が導出されるので、ロード後もワールドマップ表示・部族の距離計算はいつでも再現できる。
保存された世界地図が実際の生成結果と食い違う、という不具合の種類をそもそも作らない。

### 2.2 ローカルマップのシードはセルから導く

セル `(x, y)` を選ぶと、ローカルマップは `cellSeed = hash(worldSeed, x, y)` で生成される。
同じ世界の別のセルは別の地図になり、同じセルを選び直せば同じ地図になる。
「ランダムで始める」は「セルをランダムに選ぶ」の意味になり、従来の
`randomSeed()` と同じ手軽さが保たれる（5 章）。

### 2.3 バイオームの分布は世界ノイズで決める

セルのバイオームは世界レベルのノイズ2枚（湿り気・険しさ、見積もり）の閾値で決める。
ローカル地形生成と同じ手法（`valueNoise2D` ＋閾値）を1段上のスケールで使うだけで、
新しいアルゴリズムは要らない。ノイズなので**隣のセルは似たバイオームになる** ——
世界地図に山脈のまとまりや森の帯が自然に現れ、「どこで始めるか」が絵として意味を持つ。

## 3. バイオーム — シナリオと同じ形の「生成レバーの束」

### 3.1 前例の確認

シナリオ（`gentle` / `standard` / `harsh`）は既に「**開始条件のレバーだけを変え、ルールは同一**」
という形で存在する。レバーは開始資源・畑数・入植者数・野生動物倍率・捕食者上限の5つ。

バイオームは**同じ形のもう1束**で、変えるのは**地形生成のレバー**である。シナリオが
「どれだけ持って始めるか」なら、バイオームは「どんな土地で始めるか」。2つは直交し、
どの組み合わせも選べる（雪深い谷で `harsh`、も可能）。

### 3.2 4種のバイオーム

現在の地形生成（森ノイズ・岩ノイズ・結晶ノイズの閾値）をそのまま使い、**閾値と密度だけを曲げる**。

| バイオーム | 性格 | 曲げるレバー（出発点） |
| --- | --- | --- |
| **草原**（meadow） | 現行の生成そのもの。基準 | 変更なし。既存の実測（地形構成比・鉱脈分布）がそのまま基準値になる |
| **深森**（deepwood） | 木は無尽蔵、農地は狭い | 森閾値 0.58 → 0.48。ベリー 26 → 40 株。鹿・兎・狼が多い。岩が少なく**鉄と結晶も少ない** |
| **岩尾根**（crag） | 石と鉱石の土地。食料が細い | 岩閾値 0.72 → 0.62。鉄・結晶の閾値も緩める。草地が減り `forage` が細る。ベリー 26 → 12 株。山羊が多い |
| **晶土**（manaheath） | マナが地表に滲む土地 | 結晶ノイズの閾値を大きく緩め、**鉱脈の下限を保証する**（下記）。野生動物は少ない。灯の気分 +5 が +6 に（マナが濃い土地の演出。乗数1つ） |

### 3.3 バイオームは design-next 提案1(a) の実装先になる

design-next.md 1.1 は「200 世界中 3 つは鉱脈が1本も無く、その世界ではフェーズ2に一度も入れない」
ことを実測し、提案1(a) として**生成時の下限保証**を挙げている。バイオームはこの提案の
自然な実装先になる —— 下限はバイオームのレバーの1つ（`minCrystalVeins`）として持ち、
**全バイオームに 0 より大きい下限**を置く（晶土は高く、深森は低く）。

これは提案1(a) を置き換えるのではなく実装する形である。受け入れ条件（8 章）に
design-next.md の a-1 / a-2（200 シード回帰・豊かな世界を変えない）をそのまま引き継ぐ。

### 3.4 生成後もバイオームは効く（ただし乗数だけ）

生成時だけでなく毎日効くレバーも少数持つ（シナリオの `predators` が毎日の補充上限として
効いているのと同じ形）。

- `forage` の回復速度（岩尾根で遅い）
- 森の再生速度（深森で速い。上限は従来どおり `forestCapacity`）
- 野生動物の補充数と種の構成比

いずれも**既存の数値への乗数**で、新しい機構は無い。

## 4. 部族 — 外の圧力に、名前と方角を与える

### 4.1 方針: 部族は実体ではなく、既存の圧力の「出どころ」

この世界の幻想要素はマナだけで、それは意図的な選択である（design-phase5-trade.md 2 章）。
部族も同じ規律で作る —— エルフやドワーフのカタログを持ち込まず、**「マナとどう付き合うか」の違い**
だけで3部族を分ける。人間しかいない世界のまま、世界観が濃くなる。

| 部族 | マナとの関係 | 世界地図上の性格 | 既存のどの圧力の出どころになるか |
| --- | --- | --- | --- |
| **灯持ち**（Lanternfolk） | 結晶を育て、灯を絶やさず、余剰を商う | 晶土の周りに集まる | **交易**（フェーズ5の行商人・晶商は灯持ちの民、という設定を与える） |
| **森歩き**（Waldkin） | マナに頼らず、森と獣で暮らす | 深森に広がる | **移住者**（植民地に流れ着く人々の多くは森歩きの出） |
| **渇き衆**（the Parched） | 鉱脈を掘り尽くし、燃やし尽くした末の流民 | 岩尾根の荒れ地を彷徨う | **襲撃**（既存の raider に所属と動機が付く） |

渇き衆は世界観の要になる。マナは**この世界で唯一再生しない資源**であり（design-next.md 1.2）、
燃料が尽きた植民地には打つ手が無い —— 渇き衆とは、**その未来を先に生きている者たち**である。
襲撃が「地図の端から来る記号」から「自分たちもそうなり得た隣人」に変わり、
ゲームの機構（枯渇）と世界の物語が同じことを言うようになる。

### 4.2 効かせ方: 距離が乗数になる

各部族の勢力圏は世界ノイズから導出される（2.1 と同じく保存しない）。選んだセルから
各勢力圏への距離が、**既存の頻度・規模への乗数**になる。

| 距離 | 効果（出発点） |
| --- | --- |
| 渇き衆の圏内・隣接 | 襲撃の規模 ×1.5・間隔短縮。岩尾根の鉱石の恵みは、この圧力とセットで来る |
| 灯持ちの圏に近い | 行商の来訪判定間隔 5日 → 3日、晶商の品揃え増（フェーズ5実装後に効く） |
| 森歩きの圏に近い | 移住者の判定間隔 3日 → 2日 |
| どの圏からも遠い | すべて基準値。静かだが助けも来ない |

**部族は実体を持たない。** 集落をシミュレートせず、関係値も持たず、外交も無い。
`runIncidents` / `runArrivals` / （実装後の）交易の来訪判定が読む**乗数のセット**が部族のすべてで、
これは「外の世界は在庫から導かれる圧力としてしか存在しない」（design-phase5-trade.md 1 章）の
拡張 —— 圧力の源に座標と名前が付いただけである。

### 4.3 名前と文言

- 襲撃ログは `N raiders are coming out of the trees` から
  「渇き衆の一団が…」の形になる（部族名は襲撃者の名前プールと文言に現れる）
- 行商人・晶商の名乗りに灯持ちを、移住者の来歴に森歩きを、それぞれ一言だけ足す
- フェーズ9（言語）が入っていれば辞書キーの追加、入っていなければ英文の変更として実装する
  （**どちらが先でも成立する**）

## 5. 開始フロー

現在の開始は「ページを開いた瞬間にランダムシードの世界が生成済み」で、New map ボタンと
シナリオ選択があるだけ。この**手軽さは守る**（「シナリオは黙って決まり、変えたいときだけ1クリック」
という既存の意図を、バイオームにも適用する）。

```
[New map]
  → ワールドマップが開く（16×16。バイオームの色分けと部族の勢力圏が見える）
  → セルをクリック → そのバイオームと近隣部族の要約が出る → [ここで始める]
  → または [おまかせで始める] → セルをランダムに選んで即開始（従来の New map と同じ1クリック）
```

- 初回ロード時は従来どおり黙って生成する（おまかせ相当）。ワールドマップを**見なくても遊べる**
- ワールドマップはプレイ中も TopBar から**閲覧だけ**できる（選び直しは不可。読み物としての地図）
- シナリオ選択は従来の位置に残る（3.1 のとおりバイオームと直交）

## 6. データモデル

`GameState` への追加は **1フィールドだけ**。

```typescript
interface GameState {
  // ...既存に加えて
  worldCell: { x: number; y: number } | null;   // null = ワールドマップ導入前のセーブ
}
```

- バイオーム・部族の勢力圏・世界地図の見た目は**すべて `worldSeed` + `worldCell` から導出**し、
  保存しない（2.1）
- `worldCell: null` の旧セーブは**草原・全部族から遠い**として扱う —— つまり従来とまったく同じ
  挙動になり、移行は `worldCell: null` を補う1段だけ（`schemaVersion` +1）
- バイオームごとの生成レバーとバイオーム名は**種類ごとの定数テーブル**（`BIOMES: Record<BiomeName, BiomeProfile>`。
  `SPECIES` テーブルと同じ形式）。部族も同様（`TRIBES` テーブル）
- `JobType` / `ResourceType` / `BuildingType` は**増えない**

## 7. バランス初期値

**すべて未実測の出発点。** バイオームごとに 200 シードの分布計測と1年ヘッドレスを行って調整する。

| レバー | 草原 | 深森 | 岩尾根 | 晶土 |
| --- | --- | --- | --- | --- |
| 森閾値 | 0.58 | 0.48 | 0.64 | 0.60 |
| 岩閾値 | 0.72 | 0.80 | 0.62 | 0.70 |
| 結晶下限（`minCrystalVeins`） | 4 | 2 | 8 | 16 |
| ベリー株数 | 26 | 40 | 12 | 20 |
| `forage` 回復 | ×1.0 | ×1.0 | ×0.6 | ×0.8 |
| 野生動物 | 基準 | 草食・狼とも多い | 山羊のみ多い | 全体に少ない |

（結晶下限は design-next.md 提案1(a) の「8本」を岩尾根の値として引き継ぎ、草原はより低い
最低保証にした。**「フェーズ2を体験できる」ことは全バイオームで保証し、「フェーズ2で暮らせる」
ことは晶土・岩尾根の売りにする**、という切り分け。）

部族の距離乗数は 4.2 の表を出発点にする。とくに渇き衆の ×1.5 は
「岩尾根＝鉱石が多いが襲撃も重い」という**恵みと圧力の交換**を作るための値で、
1年ヘッドレスで植民地の生存率を見てから確定する。

## 8. 段階と「動いたと言える条件」

| 段階 | 内容 | 動いたと言える条件 |
| --- | --- | --- |
| **A** | バイオーム（生成レバー束・下限保証・毎日の乗数） | 4バイオームすべてで生成が成立し、1年ヘッドレスが破綻しない／全バイオームで結晶下限を満たす（design-next a-1 の 200 シード回帰をバイオーム別に）／草原の生成結果と1年計測が**導入前と完全一致**（既定バイオーム＝現行、の保証） |
| **B** | ワールドマップ（導出・選択UI・おまかせ・閲覧） | 同じ `worldSeed` から毎回同じ世界地図が導出される／セルを選ぶと対応するバイオームの地図が生成される／同じセルを選び直すと同じ地図になる／おまかせが1クリックで従来どおり動く |
| **C** | 部族（勢力圏の導出・距離乗数・名前と文言） | 渇き衆の圏の近くで襲撃の規模・頻度が実際に上がる（ヘッドレスで距離2水準を比較）／森歩きの圏の近くで移住が実際に速い／どの圏からも遠いセルでは全乗数が 1.0／旧セーブ（`worldCell: null`）の挙動が従来と一致する |

- **C のうち交易への接続だけはフェーズ5の実装後**に効く（それまで灯持ちは世界地図上の表示と
  設定文言のみ）。襲撃・移住への接続はフェーズ5と無関係に動く
- セーブ往復: `worldCell` を含む状態が JSON 往復で一致し、v(現行) のセーブが読める
- 性能: ワールドマップの導出は開始時と閲覧時だけ走らせ、tick パイプラインには入れない。
  距離乗数は開始時に一度計算すれば不変なので、毎 tick のコストはゼロ

## 9. リスクと非目標

| リスク | 対策 |
| --- | --- |
| バイオームが「正解の1択」になる（晶土だけが選ばれる等） | 恵みと圧力を必ずセットにする（晶土は動物が少ない、岩尾根は渇き衆が近い）。1年ヘッドレスの生存率をバイオーム間で比較して調整 |
| 選択画面が新規プレイヤーの最初の壁になる | おまかせを常に用意し、初回は黙って生成する（5 章）。ワールドマップは見なくても遊べる |
| 深森・岩尾根で既存の受け入れ条件（生存ループ）が成立しない | 段階Aの1年ヘッドレスをバイオーム別に回し、成立しないバイオームはレバーを緩める。基準は「草原と同じ操作で生き残れる」ではなく「そのバイオームなりの手を打てば生き残れる」 |
| 部族の設定が文言だけの飾りになる | 各部族を必ず既存の圧力1つに接続した（4.1 の表）。接続の無い部族は足さない |
| 旧セーブの挙動が変わる | `worldCell: null` = 完全に従来どおり、を受け入れ条件で固定（8 章 C） |

**非目標（この段階では入れない）**:

- **キャラバン・地図間の移動・複数マップのプレイ**（1 章。この線は引き続き越えない）
- **部族との外交・評判・同盟・戦争**。部族は乗数のセットであって交渉相手ではない
  （design-phase5-trade.md 10 章「商人は対話相手ではない」と同じ線）
- **部族の集落のシミュレーション**。世界地図上の勢力圏は色分けであって、中で誰かが暮らしてはいない
- **世界地図上の時間経過・勢力圏の変動**。世界は `worldSeed` から導出される静的な文脈で、動かない
- **気候・気温**。バイオームは地形生成のレバーであって温度場ではない（design.md 9 章の保留を維持）
- **開始地点の複数入植地・再入植**。1つの世界で遊ぶのは1つのセルだけ
