## 1. 位置づけ — 3つの変更は1本の因果で繋がっている

このフェーズは3つの変更を含むが、独立した3件の寄せ集めではない。

```
鉱石を足す（鉄）
  → 使い道が要る → 家具（鉄と木を消費し、暮らしの質に効く）
  → 建築の種類が 15 → 20 に増える → メニューが縦積みのまま溢れる → 階層化
```

現在の建築メニュー（`Toolbar.tsx`）は **Build グループに16ボタンをカテゴリなしで縦に並べ、
あふれた分は親サイドバー（幅 260px）のスクロールに任せている**。建物13種の時点で既に
1画面に収まるかどうかの境目にあり、家具を足せば確実に溢れる。したがって階層化（5 章）は
装飾ではなく、このフェーズの追加を成立させる条件である。

## 2. 鉱脈の一般化 — マナ結晶の前例を「表」にする

### 2.1 前例の確認

マナ結晶は次の形で入った（design.md 11 章）:

- 資源ではなく**地形**として置く（`TerrainType` の `crystal`。岩盤の奥にだけ生成）
- 採掘は**新規ジョブを作らず既存 `mine` の対象拡張**で済ませる
- 産出の分岐は `execute.ts` にある —— `crystal` なら `manaCrystal` を 6、それ以外の岩は `stone` を 20

この形は正しかったが、分岐は**2種を前提にした if 文**である。3種目を足す前に、
これを**表**にする —— 「地形 → 産出資源と量」の対応表（`VEIN_YIELD`）を1つ置き、
`execute.ts` と `mana.ts`（自動採掘機。同じ分岐が既にもう1箇所ある）の両方がそれを引く。

**新しい機構ではない。** 既にある分岐の置き場所を、2箇所の if 文から1枚の表に変えるだけ。
以降、鉱石を足す作業は「表に1行・地形生成に1判定・型に1メンバー」になる。

### 2.2 生成

鉄鉱脈（`ironVein`）はマナ結晶と同じく岩盤の中に置くが、**浅い**ところに出す。
現在の結晶は、岩ノイズが濃い所（`s > 0.86`）**かつ別シードの結晶ノイズが閾値（0.62）を超えた所**
にだけ出る（`worldgen.ts`）。鉄はこの形をそのままなぞり、岩ノイズの条件だけを浅くする ——
`s > 0.78` かつ鉄ノイズ（別シード）が閾値超え、を出発点にする（見積もり）。

意図は2つ。

1. **マナ結晶より手前で出会う。** 掘り始めてすぐ見つかる鉱石が1つあると、採掘が
   「石を得る作業」から「何が出るかを見る行為」に変わる
2. **マナ結晶の希少性を侵さない。** 岩盤の最深部は引き続き結晶の場所で、鉄はそこに割り込まない

分布は実装時に**マナ結晶と同じ方法で 200 シード数える**（design-next.md 1.1 の計測を鉄でも行い、
「鉄ゼロの世界」が何世界あるかを確認してから閾値を決める）。

### 2.3 既存セーブへの後付け

v9→v10 の移行が完全な前例になっている —— 既存の `stone` タイルへ世界シードから決定論的に
`crystal` を後付けし、全貯蔵ゾーンの `accepts` に新資源を足した。鉄も同じ1段を書く
（`schemaVersion` を実装時点の値から +1）。

## 3. 鉄 — 2つ目の鉱石であり、道具と武器の上位素材になる

`ResourceType` に `iron` を足す（4種 → 5種）。**このフェーズで足す鉱石は鉄の1つだけ**である
（「鉱石の種類」の複数化は 2.1 の表がやる。3つ目以降は 9 章の非目標）。

鉄を選ぶ理由は、使い道が**このフェーズの中と外の両方にある**から。

| 使い道 | どこで |
| --- | --- |
| 家具の材料（金具・脚・蝶番） | 本フェーズ 4 章 |
| 作業具・狩猟具・武器の**上位素材** | フェーズ8。同設計案 5 章の道具は木と石で足りる設計になっており、鉄はそこに上位段を足す受け皿になる。**同設計案で唯一材料が未決の防寒着は、鉄では解決しない**（未決のまま残る） |
| 建築の上位素材 | 将来（鉄扉・格子など。今回は入れない） |

`ResourceType` の追加は波及が大きい（`RESOURCE_TYPES` / `RESOURCE_LABELS` / アイコン /
貯蔵ゾーンの `accepts` / セーブ移行）。このうちラベルとアイコンは `Record<ResourceType, ...>` 型なので
**追加漏れがコンパイルエラーで捕まる**が、配列である `RESOURCE_TYPES`・既存ゾーンの `accepts`・
セーブ移行は型では捕まらないので、受け入れ条件のテストで固定する（8 章A）。
運搬・貯蔵・予約のチェーンは資源型に対して既に汎用で、無改造で動く
（`manaCrystal` 追加時に確認済みの性質）。

## 4. 家具 — 効かせ先はすべて既存の系統

### 4.1 方針: 家具は新しいニーズを作らない

快適・美しさは**ニーズにしない**と決めてある（design.md 5 章 —— 床・寝床・灯は既に気分の思考として
載っており、バーを増やしても同じことを二重に言うだけ）。家具はこの判断を踏襲し、
**すべて既存の3系統（思考・睡眠回復・娯楽回復）への接続**として実装する。
新しいニーズ・新しいゲージ・新しいジョブは1つも増えない。

### 4.2 追加する5種

| 家具 | 効かせ先 | 効果（出発点） | 材料に鉄が要るか |
| --- | --- | --- | --- |
| **食卓**（table） | 思考 | 半径2以内で食事すると「食卓で食べた」+3 | 要る（脚の金具） |
| **腰掛け**（stool） | 思考 | 食卓の隣にあると食卓の思考が +3 → +4 に | 不要 |
| **戸棚**（dresser） | 睡眠回復 | 半径2以内のベッドの回復に ×1.15 | 要る（蝶番） |
| **安楽椅子**（armchair） | 娯楽回復 | 炉端の休息と同型の休息先。回復 ×1.3 | 不要 |
| **石像**（statue） | 思考 | 半径4以内の入植者に「見事な石像」+3 | 不要（石の使い道を増やす） |

選定の基準は「**既存のどのフックに刺さるか**が実装前に言えること」。

- 食卓・腰掛け・石像は**魔力灯と同型**（半径内の入植者の気分に思考を足す。`manaLamp` の
  +5 と同じ機構で、思考の種類が違うだけ）
- 戸棚は**特性 `heavySleeper`（rest ×1.35）と同型**（睡眠回復への乗数。掛かる場所も同じ）
- 安楽椅子は**炉端（hearth）と同型**（`relaxing` 活動の対象がもう1つ増えるだけ）

### 4.3 マイナスの思考は入れない

RimWorld には「床で食べた」のペナルティがあるが、今回は**プラスの思考だけ**にする。
食卓の無い既存の植民地にマイナスを後付けすると、セーブを読んだ瞬間に全植民地の気分が下がり、
1年計測の成立条件が変わる。**家具は「あると良くなる」であって「無いと悪くなる」ではない**。
マイナス側は、家具が行き渡った実測を見てから別途判断する（9 章）。

## 5. 建築メニューの階層化 — スクロールで解決しない

### 5.1 現状の事実

- Build グループは**フラットな16ボタン**（建物13 + Storage + Pasture + Cancel）。
  カテゴリも折り畳みも無く、あふれは親サイドバー（260px 幅）の縦スクロール任せ
- 建物の表示名が **`Toolbar.tsx` と `SelectionPanel.tsx` で二重定義**され、既に食い違っている
  （`'Wall'` / `'Wooden wall'`）
- ショートカットキー（`useKeyboardShortcuts.ts`）とヒント文（`Toolbar.tsx` 直書き）を合わせると
  **三重管理**になっている

### 5.2 設計: カテゴリ切替式（アコーディオンにしない）

Build グループを**カテゴリ切替**にする。カテゴリ見出しを横一列に並べ、選んだカテゴリの
ボタンだけを下に出す。

```
[構造] [家具] [魔力] [区域]     ← 常に1行
┌──────────────────┐
│ Wall        wood 5    │  ← 選択中カテゴリのボタンのみ（最大7個）
│ Stone wall  stone 8   │
│ ...                   │
└──────────────────┘
```

| カテゴリ | 中身 | 個数 |
| --- | --- | --- |
| 構造 | wall / stoneWall / floor / stoneFloor / door | 5 |
| 家具 | bed / hearth / table / stool / dresser / armchair / statue | 7 |
| 魔力 | manaFurnace / manaConduit / manaLamp / manaExtractor / manaTurret | 5 |
| 区域 | farmPlot / Storage / Pasture | 3 |

- **表示されるボタン数の上限がカテゴリ内の最大数（7）で頭打ちになる。** 全カテゴリ同時展開の
  アコーディオン式だと、追加のたびに合計が伸びて元の問題に戻るので採らない
- 選択中のカテゴリは `localStorage`（フェーズ6のサイドバー開閉と同じ扱い。`GameState` に入れない）
- Orders / Animals グループは触らない（それぞれ5・4個で溢れていない）

### 5.3 定義は1枚の表に集める

カテゴリ分けを機に、建築メニューの定義を1枚の表（`BUILD_MENU`: 種類・カテゴリ・表示名・
ショートカットキー）に集約し、ボタン一覧・表示名・ショートカット・ヒント文の全部がそこから
導出されるようにする。5.1 の二重・三重管理はこの表で消える。
フェーズ9（言語）が入る場合、表示名の列は辞書キーになる —— **どちらが先でも成立する**。

## 6. データモデル

`GameState` への追加フィールドは**無い**。家具はすべて既存の `buildings` に載る。

| 型 | 追加 | 備考 |
| --- | --- | --- |
| `ResourceType` | `iron` | 4種 → 5種（3 章） |
| `TerrainType` | `ironVein` | 4種 → 5種。`isRock()` に1メンバー追加 |
| `BuildingType` | `table` / `stool` / `dresser` / `armchair` / `statue` | 15種 → 20種。既存の並列テーブル（コスト・HP・通行）に各1行 |
| `JobType` | 追加なし | 採掘は `mine`、設置は `build`、材料運搬は `haul` のまま |
| `ColonistActivity` | 追加なし | 安楽椅子は既存 `relaxing` の対象拡張 |

新しいテーブル:

- `VEIN_YIELD: Partial<Record<TerrainType, { resource: ResourceType; quantity: number }>>` ——
  採掘産出の一元表（2.1）。`crystal` と `ironVein` の2行から始まる
- `BUILD_MENU` —— 建築メニューの一元表（5.3）
- 家具の効果値（半径・乗数・思考の強さ）は `MANA_DRAW` と同じく**種類ごとの定数テーブル**
  （個体の性質ではなく種類の性質だから。`Building` にフィールドは増やさない）

セーブ: `schemaVersion` +1 を1段（既存 `stone` への鉄鉱脈の後付け + `zone.accepts` へ `iron` 追加。
v9→v10 と同型）。新しい `BuildingType` は既存セーブに存在しない状態で正しく読めるので移行不要。

## 7. バランス初期値

**すべて未実測の出発点。** 分布と1年計測で調整する。

### 7.1 鉄

| 項目 | 値（見積もり） | 意図 |
| --- | --- | --- |
| 生成閾値 | `s > 0.78` かつ鉄ノイズ `> 0.55` | 結晶（`s > 0.86` かつ結晶ノイズ `> 0.62`）より浅く、多い |
| 1鉱脈の産出 | `iron` 8 | 石（20）より少なく、結晶（6）より僅かに多い |
| 目標分布 | 中央値でマナ鉱脈の 2〜3 倍の本数 | 200 シードで数えてから確定（2.2） |

### 7.2 家具のコストと効果

| 家具 | コスト | HP | 通行 |
| --- | --- | --- | --- |
| 食卓 | 木 10 + 鉄 2 | 60 | 塞ぐ |
| 腰掛け | 木 6 | 40 | 塞がない |
| 戸棚 | 木 15 + 鉄 4 | 80 | 塞ぐ |
| 安楽椅子 | 木 12 | 60 | 塞がない |
| 石像 | 石 15 | 120 | 塞ぐ |

効果値は 4.2 の表のとおり。検証の勘所は「**戸棚 ×1.15 が特性 `heavySleeper`（×1.35）を
上回らない**」—— 家具は個人の資質より弱い、という序列を出発点にする（超えたら物語より家具が強くなる）。

## 8. 段階と「動いたと言える条件」

段階は A → B → C だが、**C（メニュー階層化）は独立していて、いつ入れてもよい**
（16ボタンの現状でも既に価値がある）。

| 段階 | 内容 | 動いたと言える条件 |
| --- | --- | --- |
| **A** | 鉱脈の一元表・鉄鉱脈の生成・移行 | 鉄鉱脈を `mine` 指定で掘ると `iron` が落ち、既存の運搬で倉に入る／自動採掘機も同じ表を引いて鉄を切り出す／旧セーブに鉄鉱脈が後付けされ、貯蔵が受け入れる／200 シードの分布を測って記録する |
| **B** | 家具5種 | 食卓の半径内で食べた入植者にだけ思考が付く／戸棚の半径内のベッドで寝ると回復が実際に速い／安楽椅子で娯楽が回復する／家具を解体してもジョブ・予約・思考が取り残されない／**家具を建てない植民地の1年計測が導入前と一致する**（4.3 の裏付け） |
| **C** | メニュー階層化・定義の一元化 | 全カテゴリで表示ボタン数が上限（7）以下／表示名の定義が1箇所になり Toolbar と SelectionPanel が一致する／ショートカットが表から導出される／カテゴリ選択が再訪時に残る |

**性能**: 家具の思考は魔力灯の気分 +5 と同じ走査に相乗りする（半径内判定を別ループで増やさない）。
1年計測の tick 予算で確認する。

## 9. リスクと非目標

| リスク | 対策 |
| --- | --- |
| 鉄ゼロの世界が生まれる | マナ結晶で実際に起きた（200 世界中 3）。閾値決定の前に分布を測る（2.2）。家具の必需品化を避けている（4.3）ので、鉄ゼロでも詰みはしない |
| 家具が強すぎて気分が常時上限に張り付く | 効果を特性より弱く置く序列（7.2）。実測で上限到達率を見る |
| カテゴリ切替が1手増えて建築が面倒になる | 最頻の構造カテゴリを既定にし、選択を記憶する（5.2）。実ビルドで操作数を確認 |
| `TerrainType` 追加でレンダラ・ミニマップの分岐が漏れる | `Record<TerrainType, ...>` の網羅チェックが効く形に寄せる（スプライト表・ミニマップ色表） |

**非目標（この段階では入れない）**:

- **3つ目以降の鉱石**（金・銀など）。表に1行足せば済む形（2.1）を作るのが本フェーズで、
  行を増やすのは使い道が現れたときでよい
- **精錬・合金・鉱石の加工**。作業台（design-next.md 提案3）の領分。鉄は掘ればそのまま使える
- **家具の品質・素材違い・色**。まず「家具がある/ない」の差が計測に出ることを確かめる
- **マイナスの思考**（4.3。実測後に別途判断）
- **鉄の建築素材化**（鉄壁・鉄扉）。壁の強度序列（木→石）に3段目を足す判断はフェーズ4の
  襲撃バランスと不可分なので、ここでは触れない
- **美しさ・快適のニーズ化**（design.md 5 章の判断を維持）

## 実装メモ（提案からの差分）

全段階（**A** 鉱脈の一元表・鉄、**B** 家具5種、**C** メニュー階層化）を実装した。
現況は [design.md](design.md) 11 章、実測値は [design-notes.md](design-notes.md)。提案からの差分:

- **鉄ノイズのしきい値は 0.55 → 0.57**。出発点の 0.55 は 200 シードで結晶の 3.1 倍となり
  目標帯（2〜3倍）を超えたため（2.2 の「測ってから確定」のとおり）
- **移行の版番号は v18→v19**。フェーズ5・6（トレーダー v15→16、地図寸法 v16→17）と
  フェーズ9（ログ構造化 v17→18）の後に積んだため、本文の「v16→v17」から繰り下がった。
  main 統合時の振り直しの経緯は notes 側
- **鉱脈ログは資源をパラメータに持つ**（`veinCutOpen` / `extractorCutVein` の `resource`）。
  フェーズ10 より古い記録には無く、その場合は魔力結晶として表示する
- **地形テクスチャの分岐はレンダラ側で一元化**（`terrainTexture`）。9 章の
  「`Record<TerrainType, ...>` の網羅チェック」はスプライト表と辞書のラベル表が担う
- **表示名は表に持たせない**。提案 5.1 の `label` はフェーズ9 の辞書（`strings.ts`）に
  一本化されたため、`BUILD_MENU` は id とカテゴリとキーだけを持つ
- **家具の半径はチェビシェフ距離**（正方形）。魔力灯（マンハッタン）とは違えたが、
  腰掛けの「隣接」（チェビシェフ1）と同じ距離関数で5種全部が書ける方を取った
- **安楽椅子の activity フィールド名は `hearthId` のまま**。改名はセーブ移行を要するため、
  「炉端か安楽椅子の id」という実態に対して名前が狭いことをコメントで明示するに留めた。
  座り先の建物種は毎 tick 引き直すので、解体された椅子が炉端係数で回復し続けることはない
- **戸棚は1つまで**（最初に見つかった1つで打ち切り）。4.2 の表は重複を明記していなかったが、
  戸棚を並べてベッドを際限なく強くできると 7.2 の「特性を超えない」序列が崩れるため
- **家具5種に新しいショートカットキーは割り当てない**。既存キー（n ベッドなど）は維持
