## 1. 位置づけ — 「提案しない」としてきたものを、なぜいま入れるか

[design-next.md](design-next.md) 6 章は研究ツリーを「複数マップ・キャラバン」と同じ行に並べ、
「どれも『1枚の地図の上の最適化パズル』という土台を変える」として提案してこなかった。
この判断を再検討すると、**同じ行に並べたのが雑だった**ことが分かる。

- 複数マップ・キャラバンが変えるのは**空間**の土台である。盤面が2枚になり、地図間の時間・
  不在中の植民地という新しい問題系が生まれる。これは引き続き採らない（フェーズ11も同じ線を引いた）
- 研究ツリーが変えるのは**時間**の形だけである。盤面は1枚のまま、「何がいつ建てられるように
  なるか」の順序が付くだけで、新しい問題系は生まれない

そして状況が変わった。MVP 時点の建築6種なら「最初から全部建てられる」が正しい —— 覚えることが
少なく、ゲートを作る意味が無い。現在は15種、フェーズ10で20種になる。**全部が最初から並ぶことは、
もはや自由ではなく提示の失敗**になりつつある（何から建てるべきかをメニューが語らない）。
現在の進行ゲートは資源コストだけで（`manaTurret` の結晶4が唯一の事実上のゲート）、
「植民地が育つと、できることが増える」という感覚を作る仕組みが無い。

研究ツリーはこの提示の問題を解く。**最適化パズルの上に置かれた、順序の層**である。

## 2. 研究の機構 — 研究台と research ジョブ

### 2.1 既存の形をなぞる

新しい機構に見えるが、部品はすべて既存の形の再利用で組める。

| 部品 | なぞる前例 |
| --- | --- |
| 研究台（`researchDesk`） | 建築の並列テーブルに1行（コスト・HP・通行）。1×1、他の建築と同じ |
| `research` ジョブ | `farm` と同型 —— 対象の建物へ行き、`WORK_TICKS` ずつ進捗を積む。研究台があり、進行中のテックがあるとき、生成器が pending を立てる |
| 進捗の置き場 | `Building.buildProgress`（0..1）と同型の数値蓄積。ただし建物ではなくテックに紐づくので `GameState.research.progress` に置く（5 章） |
| 資源を要求するテック | **魔導炉の燃料補給と同型** —— 研究台への `haul` ジョブが立ち、届いた資源が消費される。`JobType` はこのために増えない |
| 研究者の徴用 | **民兵と同型** —— 専用の徴兵UIを作らず、仕事優先度表の `research` 列が有効な入植者が研究者になる |

### 2.2 仕事の列は 7 → 8 になる

`JobType` に `research` を足し、仕事優先度表の列も1つ増やす（7列 → 8列）。
スキルにも `research` を足す（7種 → 8種。作業速度がレベルで伸びる、他のスキルと同じ扱い）。

**列を増やすのは初めてではない予定である** —— design-next.md 提案3（作業台と調理）が既に
`craft` で 7 → 8 列を予告しており、どちらが先に実装されても「列がもう1つ」の前例になる。
両方入ると9列で、サイドバー幅 300px に収まるかは**実ビルドで測る**（フェーズ6のサイドバー
再配置と絡むなら、そちらの判断に従う）。

`research` の既定優先度は **3（最低）** にする。移住してきた入植者が黙って机に向かう、という
プレイヤーの意図しない挙動を避けるためで、研究を始めるには (1) 研究台を建て、(2) テックを選び、
(3) 誰かの列を上げる、という**3つの明示的な行為**が要る。

### 2.3 テックは1つずつ進める

進行中のテックは同時に1つ（`research.current`）。研究パネルでテックを選ぶと、研究台に
ジョブが立つ。完了すると解禁され、次を選ぶまで研究ジョブは生成されない。
キューは作らない —— 「次に何を研究するか」は数日に一度の決断で、キューで自動化するほどの
頻度がない（design-next.md 提案3が「レシピのキューと繰り返し指定」をやらないことに
置いたのと同じ判断）。

## 3. 研究ツリーの中身 — 解禁するのは「新しいもの」だけ

### 3.1 既存の建築15種は取り上げない

研究の導入で最も危険なのは、**既に建てられたものを後からロックする**ことである。
既存のセーブを読んだ瞬間に「昨日まで建てられた壁が建てられない」植民地が生まれ、
セーブ互換の約束（design.md 8 章）が実質的に破れる。

したがって**既存の15種（＋フェーズ10の食卓・腰掛け）は永久に研究不要**とする。
研究が解禁するのは**このフェーズ以降に増えるもの**だけ —— 具体的には、フェーズ10の家具の
上位半分と、将来のフェーズ（作業台・装備・フェーズ5の交易柱など）が足すものである。

食卓・腰掛けを研究不要側に残すのは意図的で、**研究無しでも家具フェーズの入り口に触れる**ように
しておく（家具の思考が気分に効くことを、研究の壁の手前で1度体験できる）。

### 3.2 初期ツリー

出発点は **4テック・2段**の小さな木にする。機構が正しいことを確かめてから伸ばす
（design-next.md 提案3が「1レシピで機構を確かめてから増やす」としたのと同じ規律）。

```
木工の心得 ──→ 鉄工の基礎
石彫の心得      晶学の初歩（要: マナ結晶）
```

| テック | 前提 | コスト（見積もり） | 解禁 |
| --- | --- | --- | --- |
| **木工の心得** | なし | 300 進捗 | 安楽椅子 |
| **石彫の心得** | なし | 300 進捗 | 石像 |
| **鉄工の基礎** | 木工の心得 | 600 進捗 | 戸棚。将来: フェーズ8の作業具・狩猟具の受け皿 |
| **晶学の初歩** | なし | 500 進捗 ＋ **マナ結晶 4**（研究台へ運搬） | 当面は解禁なし（将来のマナ系設備の受け皿）。**入れるのは資源要求テックの機構を1本で検証するため** |

晶学が「解禁なし」で入るのは奇妙に見えるが、目的が違う —— 2.1 の「資源を要求するテック」は
機構として独立にテストが要り、その1本目をここで固定する。解禁物は将来のフェーズが持ってくる
（受け皿を先に作ると空でも役に立つ、というのは魔力インフラで学んだ形）。

テック名・肩書き・プリセット名の表示は、現行の言語方針（UI 文言は英語）では
Woodcraft / Stonecarving / Ironwork / Crystallography、Miner / Researcher、Farmer / Builder 等になる。
フェーズ9（言語）が入っていれば辞書キーの追加になる —— **どちらが先でも成立する**
（フェーズ11 4.3 と同じ扱い。本書の日本語名は ja 辞書の出発点）。

### 3.3 ロックは見える形で出す

守るべき原則は「**プレイヤーに見えない失敗を作らない**」。未解禁の建築はメニューから
**消さない** —— フェーズ10で階層化された建築メニューに**灰色で表示し、必要なテック名を添える**。
「ここに何かがある。開け方も書いてある」が、研究する動機の見せ方そのものになる。

目標パネル（`goals.ts`）に「最初の研究を終える」を1項目足す。既存の目標と同じく
現在の状態から導出する（研究台の有無と `unlocked` の数から）。

## 4. 職業 — 新しい機構ではなく、既にある3つの束ね直し

### 4.1 「職業」に相当するものは、実は3つ既にある

| 既存の機構 | 何を決めているか |
| --- | --- |
| `workPriorities`（仕事優先度表） | **誰が何をやるか**（0=やらない、1〜3） |
| `skills`（7種、レベルは導出） | **誰が何を得意か**（レベル×8% の速度差、経験で育つ） |
| `assignWorkBySkill`（一括ボタン） | 得意分野を優先度に反映する唯一の自動化 |

さらに民兵の前例がある —— 「狩猟列が有効な入植者が民兵になる」。専用の職業フィールドを
作らず、**既存の優先度表を役割の宣言として読む**、という形が既に1つ動いている。

### 4.2 職業は「保存される新フィールド」にしない

職業を `Colonist.profession` として保存する案は採らない。理由は2つ、どちらも既存の原則から出る。

1. **保存された導出値は実態と食い違う**（design.md 4 章）。農夫と保存されている入植者が
   実際には建築ばかりしている、という状態を作れてしまう。スキルと優先度という実態が既にあるのに、
   それと矛盾しうる第二の宣言を保存する理由が無い
2. **機構が二重になる。** 職業に速度ボーナスを付けると、スキル（レベル×8%）と同じことを
   二重に言うことになる。専門化の機構は既にスキルがやっている

代わりに職業は**2つの導出**として実装する。

| 導出 | 内容 |
| --- | --- |
| **肩書き** | 最高レベルのスキルから導出して入植者パネルに出す（`Mining` が最高なら「坑夫」）。同率は先頭勝ち。レベル 0 ばかりなら「入植者」。表示だけで、シミュレーションは読まない |
| **職業プリセット** | 優先度表の上に置く一括設定ボタン（「農夫」「建築士」「研究者」…）。押すとその職業の優先度の束を適用する。`assignWorkBySkill` と同じ階層の**UI の道具**であり、保存されるのは適用結果の `workPriorities` だけ |

「研究者が必要」という要件はこの形で満たされる —— 研究者とは `research` 列を上げた入植者のこと
（民兵と同じ定義の仕方）であり、プリセット「研究者」はそれを1クリックにする。
肩書きは研究を続けた入植者に「研究者」と表示され、実態に**必ず**追随する（導出だから）。

## 5. データモデル

```typescript
type TechName = 'woodcraft' | 'stonecarving' | 'ironwork' | 'crystallography';

interface ResearchState {
  current: TechName | null;                 // 進行中のテック。null = 未選択
  progress: Record<TechName, number>;       // 積んだ進捗（完了後も残す。導出でなく履歴）
  unlocked: TechName[];                     // 完了したテック
}

interface GameState {
  // ...既存に加えて
  research: ResearchState;                  // 追加フィールドはこの1つ
}
```

| 型 | 追加 | 備考 |
| --- | --- | --- |
| `BuildingType` | `researchDesk` | 既存の並列テーブルに1行 |
| `JobType` | `research` | 9種 → 10種。優先度列は 7 → 8（2.2） |
| `SkillName` | `research` | 7種 → 8種 |
| `Colonist` | 追加なし | 肩書きは導出、プリセットは UI（4.2） |
| テック定義 | `TECHS: Record<TechName, TechProfile>` | 前提・コスト・資源要求・解禁物。**種類の性質なのでセーブに入らない**（`SPECIES` と同じ） |
| 解禁判定 | `isUnlocked(state, buildingType)` | 建築メニューと `placeBuildingBlueprint` の両方が呼ぶ（UI だけで判定すると、UI を迂回した操作が見えない失敗になる） |

セーブ: `schemaVersion` +1 を1段。補うのは `research`（空の初期値）、全入植者の
`workPriorities.research = 3` と `skills.research = 0`。**旧セーブで解禁済みにする救済は不要** ——
3.1 のとおり既存の建築はロックしないので、旧セーブは何も失わない。

## 6. バランス初期値

**すべて未実測の出発点。**

| 項目 | 値（見積もり） | 意図 |
| --- | --- | --- |
| 研究台コスト | 木 20 ＋ 石 5 | ベッド（木12）より重く、魔導炉（石25＋木10）より軽い |
| `WORK_TICKS.research` | 50 | farm(25) より重く、mine(60) より軽い |
| 1回の作業で積む進捗 | 10 × 速度係数 | スキル・特性・気分の係数がそのまま掛かる（`workRate` を流用） |
| 木工の心得 300 進捗 | 入植者1人・優先度1で**約1日**（見積もり） | 「数日に一度の決断」の周期を作る（2.3） |
| 鉄工の基礎 600 進捗 | 同・約2日 | 2段目は1段目より重い |

検証の勘所: **研究専任1人の食い扶持が成立するか**。3人開始の植民地で1人を研究に立たせると
生産が 2/3 になる —— それでも回るのか、5人まで待つのが正解になるのか、を1年ヘッドレスで測り、
「研究はいつから始めるのが成立するか」を design-notes.md に実測として書く。

## 7. 段階と「動いたと言える条件」

| 段階 | 内容 | 動いたと言える条件 |
| --- | --- | --- |
| **A** | 研究台・research ジョブ・木工／石彫（進捗のみのテック）・解禁表示 | 研究台＋列有効＋テック選択で進捗が進み、完了で安楽椅子・石像が建てられるようになる／未解禁の建築がメニューに灰色＋テック名で見える／解禁前に `placeBuildingBlueprint` を呼んでも置けない（UI 迂回の防止）／**研究しない植民地の1年計測が導入前と一致する** |
| **B** | 資源要求テック（晶学）・前提つきテック（鉄工） | 晶学を選ぶと結晶4の `haul` が研究台に立ち、届くまで進捗が始まらない（炉の燃料と同型）／鉄工は木工完了まで選べない／研究台を解体してもジョブ・予約・運搬中の資源が取り残されない |
| **C** | 職業（肩書きの導出・プリセット） | 肩書きが最高スキルに追随して変わる（研究を続けると「研究者」になる）／プリセット適用が優先度表を宣言どおりに書き換える／プリセットは保存されず、適用結果の優先度だけが保存される |

- セーブ往復: `research` を含む状態が JSON 往復で一致し、旧セーブが移行1段で読める
- 目標: 「最初の研究を終える」が研究台の無い植民地に出て、1テック完了で消える（3.3）
- テスト方針: 解禁判定は**状態からの純関数**なのでヘッドレスでそのまま固定できる。
  8列になった優先度は既存のコア側テスト（`assignWork.test.ts` / `jobs.test.ts`）に列を1つ足す形で
  検証する（`WorkPriorityTable` 自体の UI テストは現存しない）

## 8. リスクと非目標

| リスク | 対策 |
| --- | --- |
| 解禁するものが少なすぎて研究が空気になる | 前提のフェーズ10（家具）とセットで入れる。以降のフェーズは「新物はまずツリーに載せる」を既定にする（載せない判断は都度明記） |
| 既存プレイの成立条件が変わる | 既存の建築はロックしない（3.1）。研究しない植民地の1年計測一致を受け入れ条件に固定（7 章 A） |
| 研究列の追加で優先度表が横に溢れる | 実ビルドで測る（2.2）。溢れたらフェーズ6（画面の再配置）の判断に接続する |
| 移住者が勝手に研究を始める | 既定優先度 3・テック未選択なら生成しない（2.2・2.3） |
| 肩書きがころころ変わって落ち着かない | 同率は先頭勝ちで安定させる。それでも揺れるなら「現肩書きに +1 レベルの粘り」を足す（実ビルドで見てから） |

**非目標（この段階では入れない）**:

- **時代・エイジ・ツリーの分岐選択**（取り返しのつかない選択は作らない。テックは全部いずれ取れる）
- **研究の加速アイテム・施設の上位版**。まず1台の研究台で周期が成立することを確かめる
- **職業の保存フィールド・職業ボーナス**（4.2。スキルが既にその機構である）
- **職業による仕事の禁止**（「農夫は建築できない」の類。優先度 0 が既にその表現である）
- **入植者ごとの研究分野の適性**。スキル `research` のレベル差が既にそれを生む
- **既存15種の再ロック**（3.1。いかなる形でも行わない）

## 実装メモ

段階A・B・C とも実装済み。設計どおりの部分（研究台1行・`research` ジョブが `farm` と同型・
資源要求テックが魔導炉の燃料補給と同型・肩書きが保存フィールドでなく導出）は繰り返さない。
差分だけを記す。実測と経緯は [design-notes.md](design-notes.md)「研究と職業（フェーズ12）」。

- **テックのコストを2.5倍に引き上げた**（木工・石彫 300→750、鉄工 600→1500、晶学 500→1250）。
  6章の見積もり「木工は1人・優先度1で約1日」を実測すると平均0.36日しか掛からず、比率を保った
  まま2.5倍したところ平均0.98日に収まった。5シードの小標本
- **資源コストの「届いた量」は研究台の `Building.requiredResources` に載せた**——テックが選ばれた
  ときに研究台の生成ループがその場でコスト行を足し、既存の haul 実行コードがブループリントと
  区別せず減らしていく。`GameState.research` に第2のフィールドを増やさずに済んだ（5章の
  「追加フィールドはこの1つ」を文字どおり守れた）
- **ロックされた建築を選んだときの断り文句を1つ足した**（`refusalLocked`、必要テック名つき）。
  既存の `refusalBuild`（地面が塞がっている／岩盤）とは原因が違うため、プレイヤーに伝える理由も
  分けた
- **職業プリセットは6種**（農夫・建築士・坑夫・木こり・狩人・研究者）。設計案4.2は例として
  「農夫・建築士・坑夫・研究者」の4つを挙げていたが、木こりと狩人も同じ形で成立するため追加した。
  ラベルは肩書きの辞書（`titleLabels`）をそのまま再利用し、プリセット専用の第2の名称表は増やして
  いない
