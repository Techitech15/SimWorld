## 1. 位置づけ — フェーズ13 が保留した2つを、条件が揃ったので開ける

[design-phase13-presentation.md](design-phase13-presentation.md) 5.2 は **BGM と Diffusion Audio
（生成モデル）を保留**し、再検討の条件を明示していた:

> 合成 SFX の質が実プレイで不満になり、かつ BGM のような「合成では作りにくい長い音」が
> 欲しくなった時点で、(a) ローカル生成モデルで作った短いループをサブセット同梱する、
> (b) 生成はするが別配布にする、の2案を比較する。

実プレイの要望で **両方が同時に来た**（「ログの通知音や BGM もあるか確認して」「重要度に応じて
音を作り分けたい」）ので、条件は満たされている。このフェーズはその再検討にあたる。

### 1.1 Diffusion Audio はこの環境では回せない —— 結論は変わったが理由は変わっていない

5.2 が挙げた3つの理由のうち、**1つ目は今も生きている**:

| 5.2 の理由 | いまどうか |
| --- | --- |
| 開発環境（コンテナ）に GPU が無く、生成モデルの実行・検証ができない | **変わらない。** `nvidia-smi` 無し・PyTorch 無し・`ffmpeg`/`sox` 無し |
| 生成した音声はファイルとして同梱することになり、単一 HTML の予算に直撃する | **これは誤りだった**（7章。実測で余裕がある） |
| 実行時合成で「音がある」を先に作り、それで足りないと分かってから判断する方が、測ってから決めるに沿う | **その手順を踏んだ結果、いま足りないと分かった** |

したがって **生成そのものは開発者の手元で行い、成果物のファイルをリポジトリに置いてもらう**形を採る。
このリポジトリの中で生成を再現することはできないので、**スプライトのような決定論的再生成は
音については成立しない**。これはトレードオフとして受け入れる（4章）。

なお、スプライト生成のノウハウがまとまっているとされる開発 Wiki（DevWiki）は参照できなかった ——
GitHub Wiki にページが作成されておらず、DeepWiki はこの環境の egress proxy に遮断されている。
Diffusion Audio の具体的な使い方はこの文書では扱わない。

## 2. 重要度の層 — 音を3つに分ける

要望は「重要な音はハッキリした音、何度も流れる重要でない音は耳障りの良い音」「うるさい音は入れたくない」。
これを**呼び出し側の裁量にせず、表の1列にする**。

| 層 | 意味 | 音の性質 | ゲイン | 最短間隔 |
| --- | --- | --- | --- | --- |
| **alarm** | 手を止めて見に行くべきこと | 立ち上がりが速い・倍音のある波形・音程差が明確 | 大 | 短い（聞き逃さない） |
| **event** | 節目。見に行かなくてよいが知りたい | 明瞭だが刺さらない | 中 | 中 |
| **ambient** | 世界が動いている感触 | 短い・柔らかい減衰・ピッチをわずかに散らす | **小** | **長い**＋同時発音数の上限 |

**迷ったら静かな側に倒す。** 「うるさい音を入れない」が他のすべてに優先する制約である。

音の割り当て:

| 名前 | 層 | 引き金 |
| --- | --- | --- |
| `raid` | alarm | 襲撃開始。**最も特徴的な音**にする（要望で名指し） |
| `alert` | alarm | critical アラート集合の増分 |
| `death` | alarm | 入植者の死 |
| `breakdown` | alarm | メンタルブレイク |
| `complete` | event | 建築完了 |
| `research` | event | 研究完了 |
| `trade` | event | 取引成立 |
| `arrival` | event | 移住者の到着 |
| `illness` | event | 病気の発症（フェーズ14 段階M-1） |
| `place` | ambient | ブループリント設置・ゾーン指定 |
| `build` | ambient | 建築が進んでいる間 |
| `animal` | ambient | 動物の鳴き声 |
| `notify` | ambient | その他の意味のあるログ行 |

## 3. 鳴らす場所 — ログ61キーを1つずつ見る

現在 `LogKey` は61種類あるのに、音が付いているのは3種類だけ。残りは**音が無いことに誰も気付けない**。

そこで `LOG_SFX` を `Partial<Record<LogKey, SfxName>>` から
**`Record<LogKey, SfxName | null>`（全キー列挙）** にする。キーを足したときに
「音を割り当てたか」を型が要求するようになる。日常的すぎる行は明示的に `null` と書く。

これは「プレイヤーに見えない失敗を作らない」（CLAUDE.md）の同型で、
ここでの見えない失敗は「音が付いていないことに気付けない」である。

**建築中の音と動物の鳴き声は、状態の差分から出す**（フェーズ13 の原則を維持）。
特に注意が要るのは次の2つ:

- **建築中**: 複数人が同時に建てても音は増えないこと。進捗の**合計が増えたか**だけを見て、
  ambient の最短間隔で間引く。
- **鳴き声**: 画面内に動物がいるかは `SfxDirector` からは見えない。頭数が0でないことだけを条件に、
  ambient よりさらに長い専用間隔でたまに鳴らす。**ポーズ中は鳴らさない。**

## 4. 音声ファイルの同梱 — 合成音を「土台」、ファイルを「差し替え」にする

**合成音を消さない。** ファイルが1つも無くてもゲームは鳴る状態を保ち、
ファイルがあればその名前の音だけが差し替わる形にする。理由は3つ:

1. ファイルの用意を待って実装が止まらない。
2. 一部だけ用意された状態でも成立する（`raid` だけ本物、他は合成、が有効な中間状態）。
3. ファイルの読み込みに失敗しても**無音にならない** —— 音が消えるのは
   「プレイヤーに見えない失敗」の一種である。

置き場所は `src/assets/audio/<名前>.<拡張子>`。`src/assets/sprites.ts` と同じく
**Vite の `import.meta.glob` で拾い、無ければ合成音にフォールバックする**。

## 5. 用意してもらうファイルの仕様

**この節がそのまま発注書になる。** ファイル名は 2 章の「名前」列と一致させること
（名前がそのままファイル名になる）。

### 5.1 形式

| 項目 | 指定 |
| --- | --- |
| コンテナ / コーデック | **`.ogg`（Opus）を推奨**、`.mp3` も可。`.wav` は非圧縮なので避ける |
| サンプリングレート | 48 kHz（Opus の素の値。44.1 kHz でも可） |
| チャンネル | 効果音は**モノラル**、BGM はステレオ可 |
| ビットレート | 効果音 64 kbps 程度、BGM 96〜128 kbps |
| 音量 | **ピークを -3 dBFS 以下**に正規化。無音の余白（先頭の間）を入れないこと |

### 5.2 効果音（13本）

**長さは短く。** 長い効果音は10倍速で重なって濁る。

| ファイル名 | 層 | 長さの目安 | 音のイメージ |
| --- | --- | --- | --- |
| `raid.ogg` | alarm | 0.6〜1.2 s | **角笛・警鐘。最も特徴的に。一度で「襲撃だ」と分かること** |
| `alert.ogg` | alarm | 0.3〜0.6 s | 低めの2音。危機だが `raid` とは明確に別物と分かること |
| `death.ogg` | alarm | 0.8〜1.5 s | 沈む一音。重い。**驚かせるのではなく、手を止めさせる** |
| `breakdown.ogg` | alarm | 0.5〜1.0 s | 不安定に揺れる音 |
| `complete.ogg` | event | 0.3〜0.6 s | 上昇2〜3音。達成 |
| `research.ogg` | event | 0.5〜0.9 s | 上昇3音。`complete` より晴れやか |
| `trade.ogg` | event | 0.3〜0.5 s | 硬貨・鈴 |
| `arrival.ogg` | event | 0.5〜0.9 s | 迎える感じの上昇音 |
| `illness.ogg` | event | 0.4〜0.8 s | 曇る音。下降 |
| `place.ogg` | ambient | **0.05〜0.15 s** | 短いクリック。**何百回も鳴る** |
| `build.ogg` | ambient | **0.1〜0.25 s** | 木槌の打撃1回。**何千回も鳴りうる。最も柔らかく** |
| `animal.ogg` | ambient | 0.2〜0.6 s | 遠くの鳴き声。**環境音の一部として聞こえる程度に** |
| `notify.ogg` | ambient | 0.15〜0.4 s | 柔らかいベル1音 |

**`place` / `build` / `animal` / `notify` の4本が最も重要。** ここが耳障りだと
「うるさいゲーム」になり、プレイヤーは音を切る。**迷ったら小さく・短く・柔らかく。**

複数のバリエーション（`animal_1.ogg` / `animal_2.ogg` …）を用意していただければ、
同じ音の連続を避けるためにランダムに選ぶ実装にする。特に `build` と `animal` は効果が大きい。

### 5.3 BGM

| ファイル名 | 長さ | 内容 |
| --- | --- | --- |
| `bgm_day.ogg` | 60〜120 s（**シームレスにループする**こと） | 昼。穏やか。作業の邪魔をしない |
| `bgm_night.ogg` | 60〜120 s（同上） | 夜。より静かに |

**BGM は「無いよりまし」では入れない。** 数十時間遊ばれる前提のループなので、
飽きる音を入れるくらいなら効果音だけの方がよい。1本しか用意できない場合は `bgm_day.ogg` だけでよい
（昼夜で切り替えず常時鳴らす）。

## 6. BGM

- 音量は効果音と**別のスライダー**にする。BGM を切って効果音だけ、が最も多い需要である。
- 昼夜で切り替える場合、**切り替えはクロスフェード**にする（`daylight.ts` が既に時刻から
  連続値を出しているので、それを混ぜ比率に使える）。
- **ポーズ中は止める**（雲の影と同じ判断）。
- 既定は**ミュートのまま**。ブラウザの自動再生制約と整合し、フェーズ13 の判断を維持する。

## 7. 配布先の判断 — 単一HTMLのままでよい（実測）

フェーズ13 5.2 は「生成した音声はファイルとして同梱することになり、単一 HTML の予算に直撃する」
としていたが、**これは測らずに書かれた見積もりで、実際には誤りだった**。

| | 実測 |
| --- | --- |
| 現在の `dist/simworld-embed.html` | **940 kB** |
| Claude アーティファクトの上限 | **16 MB** |
| 余裕 | 約 **15 MB** |

効果音13本（各 5〜20 kB）＋ BGM 2本（各 1〜2 MB）を data URI で入れても、
base64 の 33% 増を見込んで **3 MB 前後**。上限には遠い。

**したがって GitHub Pages への切り替えは、容量を理由には必要ない。**
切り替えるとすれば理由は容量ではなく配布のしやすさ（URL の共有・検索・ファイル分割）であり、
それは別に判断すればよい。現時点ではアーティファクトのまま続ける。

## 8. 段階と「動いたと言える条件」

### 段階 S-1: 重要度の層・音量スライダー・鳴らす場所（合成音のみ）

1. 10倍速で1日回しても ambient の音が最短間隔を割らない。
2. alarm は間引かれすぎない（襲撃が起きたのに音が出ない、が起きない）。
3. `LOG_SFX` が**全 `LogKey` を網羅**している（型と本数の両方で確かめる）。
4. 建築中の音が、複数人が同時に建てていても最短間隔以上には鳴らない。
5. 動物の鳴き声がポーズ中に鳴らない。
6. 音量がスライダーで変わり、再訪時に残る。`GameState` には入らない。

### 段階 S-2: 音声ファイルの同梱

1. **ファイルが1つも無くても、S-1 の合成音で鳴る。**
2. ファイルを置くと、その名前の音だけが差し替わる。
3. 読み込みに失敗しても**無音にならない**（合成音に落ちる）。
4. `npm run build:single` が通り、data URI で同梱され、**外部リクエストはゼロのまま**。
5. 単一 HTML のサイズを実測して記録する。

### 段階 S-3: BGM

1. 効果音と独立した音量スライダーで鳴る／止まる。
2. ポーズ中は止まる。
3. ループの継ぎ目が聞こえない。
4. 既定はミュートのまま。

## 9. リスクと非目標

### 9.1 受け入れるトレードオフ

**音声ファイルを入れた時点で、`docs/design.md` 12章の「決定論的に再生成できる」が音には
成立しなくなる。** スプライトは `npm run sprites` で誰でもバイト単位に再生成できるが、
音声は生成環境がこのリポジトリの外にあるので再現できない。

これは意識的な後退である。代わりに次を守る:
- **合成音を消さない**（4章）。ファイルが無い状態でもゲームは完全に成立する。
- ファイルは `src/assets/audio/` にまとめ、**どの音がファイルでどの音が合成かが一目で分かる**ようにする。

### 9.2 非目標

| 入れないもの | 理由 |
| --- | --- |
| 位置による音の定位（パン・距離減衰） | 見下ろし視点の俯瞰ゲームで、音源は常に画面外にもある。定位は情報にならず、うるさくなる方向にしか効かない |
| ジョブごとの作業音の作り分け（伐採・採掘・収穫…） | `build` 1種で足りる。増やすほど10倍速で濁る |
| 声・台詞 | 入植者に固有の声を与えると、8人の植民地では繰り返しが露骨になる |
| 音による通知の代替 | 音は**アラートの補助**であって、音でしか分からない情報は作らない（ミュートが既定なので、音だけの情報は届かない） |

## 実装メモ（提案からの差分）

### 段階 S-1（重要度の層・鳴らす場所・音量スライダー）

層の実数は次のとおり。**「うるさい音を入れない」が最優先の制約**なので、ambient は
ゲインで 1/3、間隔で 8 倍に離してある。

| 層 | ゲイン | 最短間隔 | 同時発音数 |
| --- | --- | --- | --- |
| alarm | 1.0 | 300 ms | 3 |
| event | 0.65 | 500 ms | 3 |
| ambient | **0.3** | **4000 ms** | **1** |

### 層だけでは足りず、音ごとの間隔の上書きが要った

最初の実装は `place` を ambient に入れ、4 秒間隔で間引いていた。**これは誤りだった。**

`place` はブループリントを置いたクリックへの**直接の応答**で、フェーズ13 5.3 も
「プレイヤーの操作への応答」を「アラート級の出来事」とは別のカテゴリとして立てている。
4 秒に押さえると、ベッドを置いて 1 秒後にもう1つ置いたとき2回目が無音になる ——
これは控えめなのではなく、**操作が壊れているように読める**。

層は「どれくらい大きいか・どれだけ重なってよいか」を決めるものとして残し、
**間隔だけは音ごとに上書きできる**ようにした（`SFX_MIN_INTERVAL_OVERRIDE`）。
上書きは両方向にある:

| 音 | 間隔 | 理由 |
| --- | --- | --- |
| `animal` | 12,000 ms（層より**長い**） | 差分駆動ではないので、何かが律速しないと毎フレーム鳴りたがる |
| `place` | 400 ms（層より**短い**） | クリックには答えが要る。ドラッグで壁を引くのは1回の差分なので1音のまま |

実装当初は `name === 'animal'` の特別扱いが1箇所に埋まっていたが、2つ目の上書きが要った時点で
表に出した。

### テストの上限も導出に変えた

「1音あたり60秒で20回未満」という平坦な上限は、4 秒間隔を前提にした数字だった。
`place` が 400 ms になった時点で成立しなくなる（毎フレーム設置し続ける合成的な最悪ケースで150回）。
**各音の実際の間隔から上限を導く**形に変え、そのうえで「クリックの応答ではない音は稀なままである」
ことを別に主張するようにした。1つの数字で2つの性質を測ろうとしていたのが元の誤りである。

### ログ61キーの割り当て

`LOG_SFX` を全キー列挙の `Record<LogKey, SfxName | null>` にした。日常的すぎる行
（スキルレベルアップ等）は明示的に `null` と書く。`colonistStarving` も `null` ——
同じ状況が既に critical アラートを立てて `alert` を鳴らすので、二重に鳴らさない。
