## 1. 段階Bを読んで見つかったこと

フェーズ2は段階Bまで実装され、結晶 → 魔導炉 → 導管 → 魔力灯が繋がった。次は段階C（自動採掘）だが、
その前に**確認しておかないと後戻りが効かなくなる**ことが1つある。

### 1.1 鉱脈の分布を測り直した

design-notes.md は鉱脈を「8世界を実測すると1世界あたり 4〜57 本」と記録している。段階Bで結晶が
**燃料**になった以上この分布は供給量そのものなので、200 シードで数え直した
（`generateWorld({ seed })` の `crystal` タイル数、seed 1〜200）。

| | 本数 |
| --- | --- |
| 最小 | **0** |
| 10 パーセンタイル | 9 |
| 中央値 | 40 |
| 平均 | 51.0 |
| 90 パーセンタイル | 110 |
| 最大 | 194 |

**8世界の 4〜57 は間違いではないが、尾を見ていない。** 実際の分布ははるかに広く、そして
**200 世界のうち 3 つは鉱脈が1本も無い**。その世界ではフェーズ2に一度も入れない —— 魔導炉を
建てても点かないのではなく、点ける燃料が地図上のどこにも存在しない。

### 1.2 燃料は再生せず、尾の世界は1年もたない

`BURN_TICKS_PER_CRYSTAL = 1980`（1日 3,000 tick の 0.66）なので、魔導炉1基は結晶を
**1日あたり約 1.5 個**燃やす。1本 6 個（`CRYSTAL_PER_VEIN`）として、世界の全鉱脈を掘り切ったときに
炉1基が燃え続けられる日数は次のとおり（1年 = 20日）。

| 世界 | 鉱脈 | 結晶 | 炉1基が燃える日数 |
| --- | --- | --- | --- |
| 最小 | 0 | 0 | **0** |
| p10 | 9 | 54 | 35.6 |
| 中央値 | 40 | 240 | 158.4 |
| p90 | 110 | 660 | 435.6 |

| | 世界数 |
| --- | --- |
| 炉1基を**1年**（20日）維持できない | **11 / 200** |
| 炉1基を**5年**（100日）維持できない | **65 / 200** |

中央値の世界は炉1基で8年もつので、**平均的には問題が無い**。問題は分布の尾で、そこは
「マナが乏しい世界」ではなく「フェーズ2が期限付きの世界」になっている。

そしてマナは**この植民地で唯一、再生しない資源**だった。森は戻り（`forestCapacity` まで）、草は生え直し、
ベリーは実り直し、野生動物は端から補充され、岩は地図の面積ぶんある。結晶だけが掘り切って終わる。

**この「唯一」は、フェーズ5 で2つ崩れた**（どちらも実装済み）。晶商から買う道（T-B）と、
晶角鹿を飼う道（F-C）である。ただし**下の分析は撤回しない** —— どちらも
「植民地が既に食料と交易柱、あるいは牧場と手懐けを回している」ことを前提にするので、
**序盤にそこへ到達できなかった植民地には効かない**。以下はその植民地についての話である。

いまはこれで実害が小さい —— 段階Bの消費先は魔力灯だけで、効果は気分 +5 である。灯が消えても
植民地は死なない。**段階C（自動採掘）で実害になる**。生産チェーンがマナに依存した状態で燃料が尽きると、
プレイヤーには打つ手が無い（掘る対象がもう無いので、掘って解決できない）。

### 1.3 マナは目標にもアラートにも出ない

`ResourcePanel` はグリッド数・供給・需要を出し、供給不足のグリッドをアラート色で示す —— ここは
段階Bで手当てされている。手当てされていないのは残り2つ。

| 場所 | 現状 |
| --- | --- |
| `src/core/goals.ts` | マナの項目が**無い**（`mana` の文字列が1つも無い）。8項目のどれもフェーズ2に触れない |
| `src/core/alerts.ts` | 同上。落ちたグリッドも空の炉もアラートに出ないので、**現場へ飛ぶ導線が無い** |

家畜の餓死・建物の損傷・貯蔵の満杯にはどれもアラートがあり、クリックで現場へ飛べる。
グリッドが落ちることは design-notes.md が「見て分かる事実1つ」として全落ちを選んだ根拠そのものなので、
その1つがアラートに出ていないのは設計意図の取りこぼしに見える。

目標パネル側はもっと単純で、**一度も結晶を掘っていない植民地は、フェーズ2の存在を知らされない**。
目標パネルはもともと「仕組みは増えたのにゲーム内にその存在を伝えるものが無い」ために作られたもので、
段階Bはまさにその状態にある。

## 2. 提案1（最優先）: 燃料の持続性を決める —— 段階Cは先に実装された

> **この提案の期限は過ぎた。** 初稿は「段階Cを積む**前に**決着させろ、依存してから変えると
> 既存のあらゆる植民地の成立条件が変わる」と書いていたが、**段階C（自動採掘機）は先に実装された**。
> 主張が外れたので、直すのは主張の側 —— 以下は「間に合わせるべき決定」ではなく
> 「**既に負っている借り**」として読むこと。緊急度は上がっている。

**目的**: 1.2 を決着させる。生産チェーンは既に自動採掘機を通じてマナに依存しており、
燃料が尽きたときにプレイヤーが打てる手は無い（掘る対象がもう無いので、掘って解決できない）。
いま燃料モデルを変えることは、既に稼働している植民地の成立条件を動かすことを意味する ——
だからこそ、これ以上マナに依存する機能を積む前に決める必要がある。

**選択肢**:

| 案 | 内容 | 効くもの | 副作用 |
| --- | --- | --- | --- |
| (a) 下限を保証する | 生成時に鉱脈が一定数を下回ったら、シードから決めた位置に足す | 0本世界（3/200）が消える | 長期の枯渇には効かない |
| (b) 再生させる | 岩の奥の結晶が、地図ごとの上限まで日次確率で戻る | 枯渇そのものが消える | マナが希少でなくなりうる |
| (c) 燃料をやめる | 消費するのは供給量だけにし、結晶は建設コストに寄せる | 枯渇が消える | 「供給し続けられるか」という段階Bの核が消える |

**(c) は採らない。** 段階Bが入れたのは「材料が足りるか」ではなく「供給し続けられるか」という第二の
制約で（design.md 11 章）、燃料をやめるとその制約が「建てられるか」に戻ってしまう。実装済みの
機能の核を後から抜くことになる。

**推奨は (a) + 上限つきの (b)。**

- **(a) は段階Cの有無にかかわらず要る。** 鉱脈ゼロの世界は、プレイヤーが何をしても
  フェーズ2に入れない。下限は控えめでよく、**8本（48 結晶 ≒ 炉32日ぶん）**を出発点として提案する
  —— 「フェーズ2を体験できる」ことは保証し、「フェーズ2で暮らせる」ことは保証しない量。
  移行経路は既にある（v9→v10 が世界シードから鉱脈を埋め込んでいるので、同じ仕組みで足せる）。
- **(b) は段階Cが入った以上いよいよ要る。** 形は森の再生とまったく同じにする ——
  `GameState.crystalCapacity`（生成時の鉱脈数）を持ち、岩に囲まれたタイルが日次確率で `crystal` に
  戻り、容量で止まる。森の再生で既に学んだ「**不動点が無い規則は放置すると地図を作り変える**」
  （森 1033 → 2253、草原 1892 → 672）の対策がそのまま使えるので、新しい失敗の仕方を増やさない。
  速さは「掘るより遅い」に置く —— 再生が採掘に追いつくと、マナは希少でなくなり石と変わらなくなる。

**やらないこと**: 炉の燃費強化（数値を1つ足すだけで枯渇の**期限が延びるだけ**であり、期限付きであること
自体は変わらない）。

**追記**: 当初ここには「結晶の交易・購入（キャラバンは 9 章の非実装リスト）」も挙げていたが、
[design-phase5-trade.md](design-phase5-trade.md) で**商人が地図の端から来る形**なら土台を変えずに済むことが分かったので取り下げた。
ただし交易が入っても **(a) の下限保証は要る** —— 理由は design-phase5-trade.md の 9 章にある。

**追記2**: [design-phase11-worldmap.md](design-phase11-worldmap.md)（バイオーム）は **(a) の実装先**を提案している ——
下限をバイオームのレバー（`minCrystalVeins`）として持ち、全バイオームで 0 より大きくする形（同 3.3 章）。
フェーズ11が先に実装されるなら (a) はそこへ吸収され、受け入れ条件 a-1 / a-2 はバイオーム別の回帰として引き継がれる。
フェーズ11を待たずに (a) 単独で入れる選択肢も引き続き有効（そのほうが安い）。

**追記3**: 追記2のとおりになった。**(a) はフェーズ11 段階Aの `minCrystalTiles`（バイオームごとの下限、
`src/core/biome.ts` の `BIOMES` 表）として実装済み** —— 草原4本〜晶土32本、全バイオームで0より大きい
（design.md 11章、design-notes.md「バイオーム（フェーズ11 段階A）」に実測あり）。**(b) の再生は
引き続き未実装のまま**。フェーズ11段階A〜Cは(b)に触れておらず、掘り尽くした世界でマナが戻ってこない
という 1.2 の問題は残っている。

**受け入れ条件**:

| | 動いたと言える条件 |
| --- | --- |
| a-1 | 200 シードのどれにも到達可能な鉱脈が下限以上ある（1.1 と同じ数え方で回帰させる） |
| a-2 | 中央値・p90 の世界の鉱脈数が実質変わらない（下限は尾だけに効き、豊かな世界を変えない） |
| b-1 | 掘り尽くした地図で、1年放置すると鉱脈が戻り始める |
| b-2 | 5年放置しても `crystalCapacity` を超えない（森の再生の回帰と同じ形） |
| b-3 | 再生速度が採掘速度を下回る（掘るより速く戻るなら希少ではない） |
| 共通 | マナ設備を建てない植民地の1年計測が、導入前と一致する |

## 3. 提案2: マナを目標とアラートに出す

**目的**: 1.3 を閉じる。提案1より小さく、独立して入れられる。

**最小実装**:

- `goals.ts` に2項目。どちらも既存の8項目と同じく**現在の状態から導出**し、操作履歴は使わない。
  - 「マナ結晶を掘る」——結晶の在庫と、地図上に露出した鉱脈の有無から。ヒント `Mine > 岩の奥の結晶`
  - 「灯りを点す」——魔導炉があり、かつグリッドが落ちていないこと。ヒント `Build > Mana furnace`
- `alerts.ts` に1〜2項目。「グリッドが落ちている」「炉が空」。既存のアラートと同じくクリックで現場へ飛ぶ。

**受け入れ条件**: マナに触れたことのない植民地に「掘る」目標が出る／炉が点いたら消える／燃料が切れたら
未達に戻る（目標は状態から導かれるので戻るはず、というのが `goals.test.ts` が既に固定している性質）／
グリッドが落ちるとアラートが出て、クリックで炉へ飛ぶ。

**やらないこと**: 目標パネルの項目数を増やしすぎない。8 → 10 で止め、それ以上は畳み方の再検討とセットにする。

## 4. 提案3: 作業台と調理

**目的**: design-phase2.5-animals.md 11 章が「作業台の概念が要る」として除外した二次加工の**入り口だけ**を作る。
肉・卵・乳・作物・ベリーはすべて同じ `food` に落ちるので、食べ物に関する選択がいま「量」しか無い。

**最小実装**: `workbench` 1種と `craft` ジョブ1種、レシピ1本。

- 調理: `food` 10 を消費し、`Item.variant: 'meal'` を持つ `food` 10 を作る
- 効果: 満腹回復が 70 → 95、加えて気分に「まともな食事」+6
- **`ResourceType` は増やさない** —— design-phase2.5-animals.md 2 章が予告した `variant`（描画とツールチップ
  だけが見る表示用タグ。シミュレーションのロジックは `type` しか見ない）の初仕事になる

仕事優先度表は 7 列 → 8 列。既存のジョブ・運搬・貯蔵チェーンは無改造で動く。

**受け入れ条件**: 生と調理済みが両方貯蔵に入る／調理済みを食べた入植者の満腹回復と気分が実際に違う／
作業台を撤去してもジョブと予約が取り残されない／`variant` を持たない既存アイテムがそのまま読める（移行不要）。

**やらないこと**: 皮革・製材・複数レシピ・レシピのキューと繰り返し指定。1レシピで機構が正しいことを
確かめてから増やす。

## 5. 推奨する順序

```
提案1（燃料の持続性）──┬─ (a) 下限保証は単独で入れられる
                        └─ (b) 鉱脈の再生
   ↓
提案2（目標とアラート）── 小さい。提案1と並行して入れられる
   ↓
提案3（作業台と調理）── variant の初仕事。フェーズ8（装備）の前提でもある
```

提案1が先頭なのは、**期限が既に過ぎているから**である。初稿では「段階Cが積まれた瞬間から
変えにくくなる」と書いたが、その段階Cは先に実装された。いま提案1は「早めに決めたいこと」ではなく
「**返済が遅れている借り**」で、これ以上マナに依存する機能を積むほど返済額が増える。

**フェーズ5 実装後の見直し**（[design-phase5-trade.md](design-phase5-trade.md) 9 章が「F-C の実測後に
確定させる」としていた判断）:

- **(b) 再生させる … 優先度を下げる。** 再生経路が2本（交易・晶角鹿）できたので、地形そのものを
  再生させる必要は薄い。しかも晶角鹿の産出は実測で炉の消費を**下回る**（1日 1.25 個 対 1.52 個、
  [design-notes.md](design-notes.md)）ので、「マナが希少でなくなる」という (b) の副作用は
  この2本では起きていない
- **(a) 下限を保証する … 最も安い保険のまま。** 鉱脈0本の世界（3/200）は、交易柱を建てる石も
  牧場を囲う木も無いまま詰まりうる。生成時の1行で消える問題に、プレイヤーの操作を前提にした
  対策を当てるのは筋が悪い

## 6. 提案しないものとその理由

| 案 | 理由 |
| --- | --- |
| ~~娯楽・快適・美しさのニーズ~~ | **この判断は外れた。** 「波及が大きいわりに得るものが小さい」として提案しない側に置いていたが、フェーズ3で `recreation` として実装された。実際にどう収まったかは [design-notes.md](design-notes.md) の「娯楽とメンタルブレイク」にある。判断を消さずに残すのは、外した記録も記録だから |
