# SimWorld

RimWorld 風の 2D ブラウザ入植地シミュレーション。設計方針ドキュメントの 1〜12 章（MVP）を実装したうえで、
生物レイヤー（[docs/design-animals.md](docs/design-animals.md)）と四季・人口増加を載せている。

```bash
npm install
npm run sprites       # ドット絵アセットを再生成（src/assets 配下）
npm run dev           # http://localhost:5173
npm test              # ヘッドレスシミュレーションのテスト
npm run build         # 型チェック + 本番ビルド
npm run build:single  # 単一HTMLに固めた版（dist/simworld.html）。ダブルクリックで起動できる
```

## 操作

| 操作                        | 内容                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------ |
| 左ドラッグ（ツール選択時）  | 範囲に対してツールを適用（伐採・採掘・撤去の指定／建築ブループリント／貯蔵・牧場ゾーン／動物指定／取消） |
| 左クリック（Select）        | 入植者を選択。選択中に地面をクリックで移動命令                                       |
| 右ドラッグ / Shift+ドラッグ | カメラのパン                                                                         |
| ホイール                    | ズーム（カーソル位置基準）                                                           |
| WASD / 矢印キー             | カメラのパン                                                                         |
| ⏸ / ▶ / ▶▶▶                 | 停止・1倍・3倍                                                                       |
| Space / 1・2・3             | 停止と再開 / 速度の直接指定                                                          |
| Esc, c, m, x, q, b, f, r, n, v, z, p, e, h, t, k | ツールの切り替え（ツールバー下部に一覧）                          |

危機（食料ゼロ・餓死・全滅）が新たに発生すると自動で停止する。ゲーム内1日ごとに専用スロットへオートセーブし、
存在するときだけ「Load autosave」が出る。

## アーキテクチャ（3章）

依存の向きは一方向で固定されている。

```
[Simulation] --tick書き込み--> [Store (GameState)] <--購読のみ-- [Rendering (PixiJS)]
                                    ^
                                    |--アクション関数（優先度変更・建築指定など）
                              [UI (React)] --selector購読--> (Storeから読む)
```

| 層          | 場所                     | 備考                                                                 |
| ----------- | ------------------------ | -------------------------------------------------------------------- |
| Simulation  | `src/core/`              | DOM にも PixiJS にも依存しない。`tickOnce(state, ctx) -> state`      |
| State Store | `src/store/gameStore.ts` | 唯一の真実源（zustand）。書き込みは tick とアクション関数の2経路のみ |
| Rendering   | `src/render/`            | PixiJS の RAF ループ。ストアへは書き込まない                         |
| UI          | `src/ui/`                | selector 単位で購読（`src/ui/hooks.ts`）                             |
| 永続化      | `src/persistence/`       | IndexedDB、`schemaVersion` とマイグレーションチェーン                |

派生キャッシュ（PathIndex・到達可能領域ラベル）は `src/core/derived.ts` の `SimContext` にあり、GameState の外・セーブ対象外（8章）。

## ジョブのライフサイクル（6章）

生成 → 候補フィルタ → 予約 → 実行 → 解放 の 5 段階だけが Job の状態遷移経路。

- 候補フィルタの条件は (a) 到達可能、(b) 対象が未予約、(c) 優先度が有効、(d) クールダウン経過。
- 同一優先度内は距離最短優先（RimWorld の距離無視方式は採らない、6章の明記どおり）。
- 運搬ジョブは搬出元アイテムと搬入先（貯蔵タイル or ブループリントの資材枠）の**両方**を予約する。
- 失敗時は `retryCount` を進めて `COOLDOWN_TICKS` 後に `pending` へ戻し、`MAX_RETRIES` 超過で `failed` にしてログへ。
  `failed` ジョブは一定時間だけ墓標として残り（同じ仕事の即時再生成を防ぐ）、期限が切れると破棄される。

到達可能性の判定は毎 tick の A* ではなく、歩行可能タイルの連結成分ラベル（地形変更時のみ再構築）で O(1) に判定し、
実際の A* は「実際に割り当てる候補」に対してのみ、1 tick あたり最大 `CANDIDATE_PATH_ATTEMPTS` 回だけ実行する。

## 設計ドキュメントからの差分（意図的な追加）

4章の型定義は「メソッドを持たないプレーンデータ」という原則を守ったまま、MVP機能リスト（9章）を成立させるために
最小限のフィールドを追加している。追加箇所は `src/core/types.ts` に `[ext]` コメントで明示した。

| 追加                                                 | 理由                                                                                                                                                                                           |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Tile.designation`                                   | 6章の「伐採指定された木」「採掘指定タイル」を保持する先が必要                                                                                                                                  |
| `Building.buildProgress` / `growth` / `sown`         | 建築進捗と畑の3段階（12章のスプライト仕様）に対応                                                                                                                                              |
| `Colonist.carrying`                                  | 運搬ジョブが荷を持つ状態を表す                                                                                                                                                                 |
| `Colonist.activity`                                  | ニーズ由来の食事・睡眠・移動命令。ジョブシステムの外側に置く（プレイヤーが優先度を付ける仕事ではないため）                                                                                     |
| `Colonist.workPriorities`                            | `setJobPriority(colonistId, jobType, priority)` が入植者ごとの優先度を前提にしている                                                                                                           |
| `Colonist.color`                                     | 12章「個体差は色替えで対応し、共通の歩行スプライトシートを使い回す」                                                                                                                           |
| `Job.workType`                                       | 実行内容（`type`）と、どの仕事列で優先度を引くか（`workType`）の分離。ブループリントへの資材運搬は「建築」の仕事として扱う（そうしないと運搬を最低優先度にした植民地で建物が永久に完成しない） |
| `Job.payloadType` / `destinationId` / `workProgress` | 運搬先と運ぶ資源、作業進捗                                                                                                                                                                     |
| `GameState.nextIds` / `log`                          | ID 採番をセーブ間で安定させるため／失敗ジョブのログ（6章）                                                                                                                                     |

その他の実装上の判断:

- **扉は MVP では常に通行可能**とし、開閉はスプライトの見た目のみ（`BLOCKS_MOVEMENT`）。
- **貯蔵ゾーンは資材コストゼロ**なので、ブループリントを経ずに完成状態で設置される。
- 1 タイルの貯蔵スタックは 1 資源種類・最大 `STACK_MAX`。

## フェーズ2以降

魔力インフラ・物語生成・防衛は MVP に一切含まれていない（9章・11章）。`ResourceType` や `BuildingType` を
拡張する形で追加できるよう、資源と建築のテーブルは `src/core/constants.ts` に集約してある。

| 拡張                               | ドキュメント                                     | 状態                       |
| ---------------------------------- | ------------------------------------------------ | -------------------------- |
| 生物レイヤー（狩猟・牧畜・捕食者） | [docs/design-animals.md](docs/design-animals.md) | 実装済み（段階 A〜D 完了） |

生物レイヤーは本編ロードマップに無い追加要素のため、フェーズ2（魔力インフラ）とは独立に着手できる
**フェーズ2.5** として位置づけ、設計案の段階 A〜D をすべて実装した。捕食者を入れるために HP と死亡を
最小構成で導入する点だけが本編 9 章の「含まないもの」からの意図的な逸脱で、その範囲と限界は
設計案の 1 章と 11 章に、実測して設計案から変えた点は 12 章に記載している。

野生動物4種（鹿・猪・鶏・狼）が徘徊・採食・逃走・捕食し、`hunt` / `handle` の2ジョブと牧場ゾーンで
狩猟・手懐け・屠殺・繁殖・産出までが既存のジョブ・運搬・貯蔵チェーンの上に載っている。
セーブは `schemaVersion` 6 で、v1〜v5 のセーブは読み込み時に自動で移行される。

## 1年放置の実測

個々の機能は数百 tick の単位で検証しているが、それらが噛み合った状態で長期に成立するかは別問題なので、
`src/core/longrun.test.ts` が無操作のまま1年（20日 = 60,000 tick）を回す。実測値（seed 8101）:

| 時点 | 人口 | 食料 | 動物 | 最高スキル |
| --- | --- | --- | --- | --- |
| 5日目（夏） | 3 | 718 | 28 | 5 |
| 10日目（秋） | 5 | 1448 | 30 | 6 |
| 15日目（冬） | 6 | 1506 | 30 | 7 |
| 20日目（春） | 6 | 934 | 28 | 7 |

入植者の死亡ゼロ、餓死ゼロ、失敗ジョブの滞留なし、1 tick あたり 0.59〜0.62 ms（予算 200 ms）。
冬に食料が 1506 → 934 まで落ちて春に回復するので、越冬の緊張は残しつつ詰まないバランスになっている。

この計測で分かったのは、既定の植民地が **1年で開始時の貯蔵庫をほぼ埋め切る**（20タイル × 75 = 1500 に対し
最大 1497）ということ。貯蔵が満杯になると運搬係は置き場所を見つけられなくなり、荷物は落ちた場所に
留まるが、これまでその理由はどこにも表示されなかった。満杯・行き場なしをアラートに追加した。

## 損傷と修理

これまで `BUILDING_HP` は誰も減らせない飾りだった。獲物に手が届かない捕食者が、間に立つ建築を齧るように
した（`gnawStructure`）。齧りは通常の噛みつきより弱く遅く、しかも他の追跡と同じ `PREDATOR_PURSUIT_TICKS`
で打ち切られる。1回の襲来で入る傷はせいぜい十数回分なので、**木の扉は3回ほどの襲来に耐え、石壁はまず落ちない**。
柵は「無敵の壁」でも「形だけ」でもなく、維持する対象になる。

損傷した建築には `repair` ジョブが自動生成される。解体と同じく独立した列は持たず **建設列** で走るので、
建設を切れば修理も止まる。資材は不要（修理は作り直しではなく手当てで、資材搬入を挟むと2つ目の
ブループリント機構になってしまうため）。損傷はアラートにも出る（40%未満で critical）。

## ミニマップ

60×60 の地図は画面に収まらないため、右サイドバー上部に 1 タイル = 1 ピクセルの全体図を置いた
（`src/ui/Minimap.tsx`）。地形・建築・牧場・指定に加えて、入植者（白）・捕食者（赤）・家畜（黄）・
野生動物（茶）が点として乗る。クリックでカメラがそこへ飛び、白枠が現在の表示範囲を示す。

描画は 60×60 の `ImageData` に直接書き込んで CSS で拡大する（`image-rendering: pixelated`）。
カメラ位置はレンダラからストアへ報告するが、タイル単位に丸めた上で変化が無ければ更新を捨てるので、
静止中のカメラが毎フレームの再描画になることはない。

## 貯蔵ゾーンのフィルタ

貯蔵ゾーンは資源ごとに受け入れの可否を持つ（選択パネルのチップで切り替え）。ゾーンは牧場と同じく
**場所**になり、隣接しないゾーンは別々の在庫になる（壁際の薪置き場と寝床脇の食料庫を別に運用できる）。
牧場は `food` だけを受け入れる＝飼い葉置き場であり、以前のように薪や石が家畜の間に積まれることはない。

フィルタを絞っても既存の在庫はその場から消えない。「そこに置いてはいけない荷物」になるだけで、
次の tick から通常の運搬ジョブとして運び出される。

## 特性（トレイト）

スキルが「その人が何をしてきたか」なのに対し、特性は「その人がどういう人か」で、生涯変わらない
（`src/core/traits.ts`）。10 種を5つの排他グループに分けてあり、早熟と晩成が同時に付くことはない。
だいたい2つ、1割は無特性で、全員が特別な植民地は誰も特別でないため。

特性はすべて **既存の数値への乗数** として実装してある。新しい仕組みを一切増やさないので、組み合わせが
特殊ケースの山にならず、特性ゼロの入植者は特性導入前とまったく同じ挙動になる（乗数の積が 1）。

| 特性 | 曲げる数値 |
| --- | --- |
| 早熟 / 晩成 | 経験値の入り |
| 勤勉 / 悠長 | 作業速度（スキルとは別に乗る） |
| 大食い / 小食 | 空腹の進み |
| 眠り上手 / 落ち着かない | 睡眠の回復・消耗 |
| 頑健 / 虚弱 | 休息中の治癒 |

## スキル

入植者は仕事の列ごとに熟練度を持つ（`src/core/skills.ts`）。実際に手を動かした tick だけが経験になり、
レベルが上がるほど同じ仕事が速く終わる（レベル10で1.8倍、`WORK_TICKS` 自体は変えない）。
`deconstruct` は建設の列で扱うため、解体も建設の熟練度を伸ばす。

開拓者と移住者は世界シードから決まる得意分野を2つ持って現れるので、「この人は狩人」「この人は大工」が
最初から成り立つ。レベルが上がるとイベントログに残り、入植者パネルに上位3つが並ぶ。
